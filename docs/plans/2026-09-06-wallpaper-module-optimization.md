## 执行阶段

### P0-A：普通生图可靠性与取消

- 每次任务使用独立请求 ID、会话和输出目录，彻底移除扫描当天目录回填成功结果的行为。
- 复用已存在的受限工具执行、取消注册、会话审计与 Host 复制结果模式；根据实际 `image_gen` 参数契约实现验收。
- 默认一次生成一张，生成数量由明确参数决定，不允许模型自行追加变体或自动重试。
- 只接收本次会话生成且通过路径、签名、大小校验的图片；元数据记录用户原始提示词及实际可确认的参数。
- 取消、关闭窗口和离开生成来源终止本次后台任务，清理临时资源，迟到结果不能覆盖当前界面。
- 保持改图和图生视频已验证的行为；共享代码只在实际消除重复时抽取。

验收：当天已有图而本次返回无效 JSON/空结果时必须报错；旧文件、会话外路径和非图片不能成功入库；取消后无迟到结果；正常结果可预览、重新找到并应用。先用确定性 fixture 覆盖失败路径，再做最少量真实生成验收。

### P0-B：完整图库与稳定分页

- 增加 Host 分页接口，返回稳定排序的条目、下一页游标和可确认的计数；保留旧接口以兼容其他调用者。
- 排序在 Host 完成，明确静图优先、修改时间和稳定 ID 的顺序，避免每页在前端重新排序导致跳动。
- 库内搜索和类型筛选作用于完整集合；切换条件重置分页，不能仅过滤已加载的 96 项。
- 明确扫描快照和刷新语义：加载过程中新增文件下次刷新出现；删除和时间相同的文件不造成重复或漏页。无效游标明确失败。
- 首先复用现有扫描和缓存设施；根据实际图库规模再确定是否需要持久索引，避免直接引入新数据库。

验收：使用至少 250 个混合媒体 fixture，所有文件可翻页访问；能搜索到第 96 项之外的文件；同时间文件、新增、删除、刷新均不重复漏项；同一视图追加时已有卡片位置稳定。

### P1-A：保留各来源浏览状态

- 把来源工作状态移入领域 hook，按来源保留查询、排序、结果、选中项、筛选、分页和滚动位置。
- 本阶段保证同一次弹窗打开期间的返回恢复；重新启动后的完整搜索历史不混入首轮交付。
- 从搜索图进入改图或视频后，可以回到原来源继续浏览；三个生成模式的提示词继续独立保存。
- 来源切换停止不再需要的网络工作；正在生成的任务继续遵守 P0-A 的取消语义，不引入后台任务队列。
- 缓存有条数和生命周期上限；账号、Pexels 凭证及来源身份变化时失效，不能恢复前一身份的私有相册数据。

验收：搜索并翻页 → 滚动选图 → 进入改图 → 返回，结果、位置和分页恢复；切换来源不额外发起重复搜索；迟到响应不能写入其他来源。

### P1-B：失败可见、可重试

- 为卡片区分缩略图失败、原图失败、加载中和成功；网络失败保留条目及原有尺寸。
- 单项重试只重新请求失败媒体，限制并发；原图失败时仍保留可用缩略图。
- 生成错误使用稳定分类，覆盖登录、额度/限流、超时、格式、上游失败、结果校验失败；无法确定原因时诚实显示未知错误。
- 生成重试由用户主动触发新的任务，不自动重复消耗额度；保留源图、提示词和选项。
- 错误文案给出对应可执行动作；不直接显示原始 CLI 日志或认证内容。

验收：模拟离线、403、429、超时、解码失败；已有卡片不消失，成功项不重载，重试后可恢复；关闭或换来源后重试结果失效。覆盖主设置窗口与独立主题编辑器。

### P2-A：收藏、元数据和文件管理

- 引入最小媒体目录记录：稳定 ID、来源、来源页/许可、已知尺寸、用户提示词、生成参数、父图关联和收藏状态。
- 为旧文件渐进补录，无法追溯的数据保持未知；兼容已有目录和文件，不要求搬迁或重新下载。
- “浏览缓存”“已收藏”“生成作品”分别记录用途。提供收藏/取消收藏和按用途查看；取消收藏不删除原文件。
- 提供单项另存为、打开所在文件夹；再补批量收藏、导出和删除，逐项报告成功与失败。
- 区分删除条目和删除文件；采用现有可用回收设施或应用内可恢复删除，定义恢复期限及同名冲突处理。
- 清理缓存先展示范围和大小，保护收藏、生成作品、当前背景及任务正在使用的源文件；不自动清理旧数据。

验收：重启后收藏和提示词仍在；生成结果可追溯源图并复用提示词；旧库正常显示；另存为不静默覆盖；批量部分失败不宣称全部成功；删除可恢复且不影响当前背景。

### P2-B：找图效率与质量

- 首批增加横图/竖图/方图、比例、最低分辨率和来源筛选，以及尺寸和文件信息查看；未知尺寸单列，不伪造满足条件。
- 远程来源仅把其真实支持的过滤参数发给上游；本地过滤标明只针对当前已加载结果，避免把筛空误报为上游无结果。
- 库内过滤走完整集合；搜索词与筛选条件共同参与缓存和分页身份。
- 先补规范 URL、文件内容的确定性去重；视觉近似去重作为后续独立项，用固定样本评估后启用，不直接删除相似原文件。
- 用固定主题集评估网络结果相关性，记录相关率、重复率、有效数量和耗时，再调整查询或排序。
- 性能先测量再优化：评估大库滚动、首批缩略图、视频封面和切换恢复，按瓶颈复用缩略图缓存或窗口化渲染。

验收：横竖图、超宽图、低清图、未知尺寸均有测试；过滤和分页相互一致；至少 500 项库做滚动与内存观察；搜索质量有前后对比，不能只靠增加结果数量宣称改善。

### P2-C：生成能力与渠道核实

- 先核对当前安装的 Grok Build、对应源码/工具 schema、官方能力说明和当前账号渠道，记录日期与版本。
- 分别列出普通生图、改图、图生视频的模型、比例、分辨率、时长及调用路径；区分官方 API 的能力与当前订阅工具的能力。
- 已有 API 文档研究不能证明订阅凭证可调用同一能力，也不能证明 API 调用走订阅额度。
- 当前渠道确实支持的选项同时补前端、Host 校验、工具参数和结果验收；不支持的保持明确限制。
- 若必须新增收费 API 渠道，先形成具体接入与费用说明，作为独立决策，不静默改路由。
- 视频 16:9 不通过拉伸原图伪装完成。核实原生行为；需要重构图时，采用明确的先改图再生视频流程并说明额外生成步骤。
- 验证分辨率使用成片实际尺寸，验证时长使用真实媒体信息。缺乏实际模型信息时只记录请求模型，不伪称已确认实际执行模型。

验收：真实支持的选项才可选择，前后端能力一致；代表性真实结果的比例、尺寸和时长匹配；对仅请求审计覆盖、尚未实际生成的组合单独标注。

最新能力报告见 `../qa/2026-09-07-wallpaper-generation-capabilities.md`：安装版为 `1.0.13 (5e9a58528b76)`，检查的本地上游源码为 `9684fa3cdbf2995e30ea8b9b637f1db008f144fc`，两者不是同一构建。源码中的 `image_to_video` 固定模型 `grok-imagine-video-1.5`，只接收图片、提示词、6/10 秒及 480p/720p；带比例的 `reference_to_video` 属于另一工作流。图片模型配置覆盖能力也不等于可选模型或账号权限清单。当前计划不承诺未证实的 1080p、模型选择或订阅额度复用；落实功能前补安装版契约和实际结果证据。

| 里程碑 | 包含内容 | 用户可感知结果 |

| M1 | P0-A、P0-B | 生图不冒用旧结果、可以取消，完整壁纸库可查可翻 |
| M2 | P1-A、P1-B | 切换不丢现场，加载失败能恢复 |
