1. **P1 — Host collection lacks a writer-stop barrier, and SSH failure still advances the phases.**

   **Evidence:** `scripts/s11-0-probe.sh:1585`, `scripts/s11-0-probe.sh:1587`, `scripts/s11-0-probe.sh:1595`, `scripts/s11-0-probe.sh:1600`, `scripts/s11-0-probe.sh:1604`, `scripts/s11-0-probe.sh:1845`; host lstat at `tools/s11-mailbox-probe/src/c8dual.rs:620`.

   `c8d_phase` checks timeout/reap/overflow/abort flags but never checks `G_ST`. An SSH disconnect with exit 255 therefore returns phase success. The driver can dispatch B while A1's remote process has an uncertain state, then dispatch A2 and run the host collector. Even on the normal path, the VM remains running throughout collection; the existing stop/run-process/absence checks occur only after `m_measure` returns. A live or disconnected guest writer can consequently change the objects between the host's phase reads and individual lstats. Neither A1 → B → A2 completion nor a quiescent host identity snapshot is established on the failure path.

   **Read-only reproduction:** evaluated the unchanged production `c8d_phase` and `m_run_c8_dual` functions in memory, replacing external operations with shell functions. With SSH exit 255 and all timeout/overflow/abort/reap flags clear, `c8d_phase` returned 0 with `G_ST=255`. Three such failures still produced the call sequence `run C8 a1`, `run C8 b`, `run C8 a2`, host collection, with no stop call.

   **Minimal fix:** stop dispatching on unexpected SSH completion and preserve a phase-specific unknown reason. The normal C8 dual dispatcher currently exits 6 because its probe deliberately returns 1 for `unknown`; account for that contract rather than requiring exit 0. Defer the host collector until the existing VM stop/run-process/absence proof succeeds, before export audit/cleanup, under the existing deadlines. If stopping cannot be proved, keep unknown/quarantine and do not take authoritative host identities. Cover disconnect-after-dispatch and stop-failure paths in the stubs.

2. **P1 — A guest-writable `result-host` can supply forged host identity fields.**

   **Evidence:** `scripts/s11-0-probe.sh:1604`, `scripts/s11-0-probe.sh:1606`, `scripts/s11-0-probe.sh:1439`, `scripts/s11-0-probe.sh:1440`, `scripts/s11-0-probe.sh:1501`, `scripts/s11-0-probe.sh:1509`; host output publication at `tools/s11-mailbox-probe/src/c8dual.rs:632` and `tools/s11-mailbox-probe/src/run.rs:530`.

   The trusted host process writes a private capture, `p8.out`, but the driver instead obtains its record from `mailbox/result-host`, inside the guest-writable export. A running guest can replace that record after the host publishes it and before `read_slot_verdict` reads it. A planted record can also survive a collector launch/publication failure: `settle_host` checks process exit status only for `ok`/`not-ack`, while every dual C8 record is `unknown`. Thus even exit 126/127 can leave a guest-provided `reason=observed` and arbitrary `host_id` in the report. Merely adding the stop barrier in finding 1 does not authenticate a record planted before shutdown when host collection fails.

   **Read-only reproduction:** the unchanged production parser accepted `v=1 op=c8d role=host verdict=unknown reason=observed n=2 counted=8,12 a_steps=FORGED b_steps=FORGED guest_id=FORGED host_id=FORGED`. With `H1_ST=127`, `G_ST=255`, and no timeout/overflow/abort/reap flags, `settle_host c8` returned 0 and retained that complete record as `unknown/observed`. This exercised parsing/settlement only, without writing an export or running a collector. Rust's closed guest-record parser prevents ordinary guest fields from injecting top-level host fields; this shared-result path bypasses that protection.

   **Minimal fix:** consume the bounded host collector's private stdout capture as the authoritative host record, with the expected `op=c8d`, role, completion status, and supervision checks. Guest phase evidence must still come from the pre-created mailbox slots. Treat the shared `result-host` as an archival copy, or compare it with the private host capture; never fall back to its contents when host collection fails. Add guest-overwrite and failed-host-launch cases. Stronger field syntax alone cannot authenticate host identity numbers.

3. **P2 — Successful rename probes exceed gcuprobe's 12-operation limit.**

   **Evidence:** `tools/s11-mailbox-probe/src/c8dual.rs:33`, `tools/s11-mailbox-probe/src/c8dual.rs:41`, `tools/s11-mailbox-probe/src/c8dual.rs:65`, `tools/s11-mailbox-probe/src/c8dual.rs:234`, `tools/s11-mailbox-probe/src/c8dual.rs:238`, `tools/s11-mailbox-probe/src/c8dual.rs:327`; limit in `docs/adr/0019-tart-mailbox-channel.md:300`. The unit test counts plan entries at `tools/s11-mailbox-probe/src/c8dual.rs:692`.

   Each admitted `rename` can issue two real renames: the measured rename and an uncounted reverse rename. For B, three objects each undergo chmod, chown, forward rename, and reverse rename, followed by b-file create/chmod/chown: `3 × 4 + 3 = 15` counted filesystem operations when all renames succeed. The report still says 12. The comment exempting the undo does not change the ADR's operation budget. Reverse-rename failure is also discarded, leaving a `.ren` object while later operations use the absent original name.

   **Minimal fix:** issue one rename attempt per planned rename and retain its resulting pathname for the subsequent unlink. This keeps B at 12 without adding hidden mutation attempts. Keep the fixed result labels, but record the actual outcome and audit any permitted `.ren` residue with its correct type. Verify actual syscall attempts, including successful renames, rather than only `plan()` entry counts.

4. **P2 — A transient replaced result slot is classified as malformed.**

   **Evidence:** `tools/s11-mailbox-probe/src/c8dual.rs:563`, `tools/s11-mailbox-probe/src/c8dual.rs:576`, `tools/s11-mailbox-probe/src/c8dual.rs:582`; replacement detection at `tools/s11-mailbox-probe/src/io.rs:425` and `tools/s11-mailbox-probe/src/io.rs:428`; virtiofs rule at `docs/adr/0019-tart-mailbox-channel.md:341`.

   `read_phase` retries ENOENT and placeholders, but its catch-all maps `RdErr::Replaced` to `Fault::Malformed`. When a pre-created result slot changes from its placeholder inode to the guest's published inode during a verified read, the IO layer correctly discards that snapshot as replaced. The new reader then stops with `a1-malformed`, `b-malformed`, or `a2-malformed`, even if the next read would contain a complete valid phase. This is explicitly a retryable virtiofs state, distinct from malformed bytes.

   **Minimal fix:** retry `RdErr::Replaced` alongside `RdErr::Absent` within the existing clamped retry/command deadline, discarding the affected bytes. Preserve malformed classification for stable invalid records and retain the retry evidence required by the virtiofs rules. Exercise placeholder-to-result replacement with the existing read hook, followed by a valid record.

5. **P2 — Identity summaries omit the ACL observation required by the C8 card.**

   **Evidence:** `tools/s11-mailbox-probe/src/c8dual.rs:273`, `tools/s11-mailbox-probe/src/c8dual.rs:279`, `tools/s11-mailbox-probe/src/c8dual.rs:281`, `tools/s11-mailbox-probe/src/c8dual.rs:288`, `tools/s11-mailbox-probe/src/c8dual.rs:292`; required observations at `docs/adr/0019-tart-mailbox-channel.md:301`.

   Both identity branches contain only stat fields; neither inspects ACLs. A mode of 0600/0700 does not describe additional ACL grants or denials, so identical uid/gid/mode tuples can have different effective cross-principal permissions. An inherited ACL can therefore explain a recorded access result while remaining completely invisible in an `observed` record. The reduced identity fields described in the implementation brief do not fulfill the referenced ADR's UID/GID/ACL observation requirement.

   **Minimal fix:** collect bounded, non-following ACL summaries on both sides and include them in the validated identity records. Distinguish no ACL from unavailable/error; an unavailable required observation must remain explicitly incomplete. Test objects with equal mode bits and different ACLs, and an ACL-query failure, without changing privileges.

6. **P2 — Unexpected contents inside the allowed `a-dir` bypass quarantine.**

   **Evidence:** `scripts/s11-0-probe.sh:1739`, `scripts/s11-0-probe.sh:1740`, `scripts/s11-0-probe.sh:1760`, `scripts/s11-0-probe.sh:1711`, `scripts/s11-0-probe.sh:1788`, `scripts/s11-0-probe.sh:1803`.

   The new audit accepts `c8/a-dir` as a directory, but scans only the mailbox root and `c8/`. It never checks that the guest-created `a-dir` is empty. If the guest leaves `c8/a-dir/unexpected` or a symlink there, the parent directory passes its name/type check; no audit failure occurs, and cleanup reports the export as `retained`. This changes the promised rule that unexpected guest names or symlinks quarantine the whole export. Nothing is recursively deleted, but the suspicious tree is incorrectly classified as ordinary retained evidence.

   **Minimal fix:** after proving writers stopped, perform a bounded no-follow emptiness check on the fixed allowed directory `c8/a-dir` before accepting the export. Any child, unproved check, or replacement must take the existing quarantine path. Apply the same rule to any allowed renamed directory residue; do not add arbitrary recursive traversal or deletion. Add hidden-file and symlink children to the audit stubs.
