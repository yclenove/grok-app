Must-fix, category (a), before merge:

1. **[P2; S5-A1] A scope-prohibited launch still enters app/confirmation approval before scope refuses it.** `gcu-core/src/action/discovery.rs:140`, `:190`, `:227`; `gcu-core/src/scope/driver.rs:215`; masked by `gcu-mcp/tests/fixture_scope.rs:626`, `:633`, `:754`, `:869`.

   Concrete schedule: open a fresh scoped connection admitting the ordinary fixture A, with the production `Approvals` provider, `auto-allow-session`, default policy and no Stop/user activity. Call `launch_app({app:"fixture.a"})`. Scoped resolution admits A, then `launch_queued` invokes `authorize` **before** reaching the wrapper's unconditional launch refusal. `PolicyEngine::evaluate` first requests an app grant (`gcu-core/src/policy/mod.rs:380`), which eval grants. The fabricated launch context has no resolved target, so Standard confirmation treats this mutation as high risk (`policy/risk.rs:141`); the changed provider denies its confirmation. The result is `approval_denied`, rather than fixed scope `app_denied`. With sensitive confirmation Off and foreground Ask, the same schedule instead reaches and denies the foreground confirmation. With eval mode absent on an interactive desktop, the first app request opens an approval card for an operation that scope unconditionally prohibits. No platform launch occurs, but ADR §3's no-approval-card rule and fixed scope-refusal contract are violated.

   This ordering is inherited from the base, not introduced by the split. It is an unclosed S5 acceptance case, not one of the accepted S1/S3 native/cache/transport residuals. The expanded matrix actually calls launch on A when iterating A3/forged-window (launch has no window parameter), but its `ScriptedApprovals` plus sensitive Off/foreground Always allow authorization to finish, so it reaches the late scope refusal and stays green. It asserts zero platform launch, not zero approval requests. The new production-provider tests only observe the denied targets (`gcu-cli/src/scope/approval_tests.rs:196`).

   Fix direction: refuse scoped launch in the router before resolution/authorization, after the existing Stop/closed-session check; retain the driver's independent refusal. Do not solve this by suppressing launch only in the MCP catalog. Add direct-core and actual MCP dispatch cases for A and C with default policy and each eval allow mode, plus a recording provider that fails if either approval callback runs. Require the fixed message, no state/images/windows, zero approval/confirmation requests and zero platform launch/read/capture/perform. Repeat with Stop latched and require `stopped_by_user`. These cases should fail on this branch by inspection.
