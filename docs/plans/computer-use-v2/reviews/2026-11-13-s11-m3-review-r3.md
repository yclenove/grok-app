## Finding

### F2 — P2: legal commented and compound attributes still bypass the production-import guard

**Evidence:** `crates/gcu-eval/tests/tart_offline.rs:1127` removes whitespace but leaves comments. At `:1133` it recognizes only an immediately adjacent `#[`/`#![`, and `:1134`–`:1136` ends an attribute at the first textual `]`, including one inside a string. The `path=` substring check at `:1138` therefore misses both legal declarations below in `mailbox/mod.rs`:

```rust
#[path/**/ = "tests"]
#[allow(dead_code)]
mod live {
    mod support;
}
```

```rust
#[cfg_attr(all(), doc = "]", path = "tests")]
#[allow(dead_code)]
mod live {
    mod support;
}
```

In the first case, the flattened attribute contains `path/**/=` rather than `path=`. In the second, `all()` enables the attributes, but the scanner stops inside the doc string before reaching `path`. Both directory-valued attributes resolve `live::support` to the existing exempt `mailbox/tests/support.rs`. That source has no internal `cfg(test)` gate; its `super::super` imports still resolve to `mailbox`. The original `#[cfg(test)] mod tests;` remains intact and passes the separate gate at `:915`.

Consequently production can reuse a source whose filesystem/environment spellings are skipped at `:934`–`:937`. This is a defect in the regression guard, not evidence that the current production sources perform that import. It uses ordinary Rust attributes, without forbidden-API aliases.

**Minimal fix:** scan attribute tokens with comment handling and balanced delimiters that respect ordinary/raw string literals. Detect `path` followed by `=` within plain and compound attributes, allowing only the existing `path = "sys.rs"` declaration in `mailbox/mod.rs`. Fail closed on unsupported attribute forms. Add both examples to `mailbox_scan_exemptions_are_exact`, including a whole-tree case that imports an exempt source containing a filesystem/environment call.
