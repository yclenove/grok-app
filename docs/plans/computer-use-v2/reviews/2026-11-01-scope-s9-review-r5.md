Residuals, category (b), and limits:

- **Accepted window-level schedules stay accepted.** Moving an element to another window of the same admitted process after its last membership proof, or replacing a same-process HWND after the final window check, is covered by the owner decision and disposable-VM boundary. The final identity-syscall/delivery interval is still not atomic. No additional blocker is raised solely for those intervals; the round-4 read-after-a-completed-message schedule is repaired by eliminating later reads and checking the exit.
- **The isolated-parent assembly remains unavailable.** The clipboard wire field alone supplies no native scope installation or ACK. Adding parent evidence without propagating the original authority into the child would be insufficient. InProcess and real eval remain outside this verdict; missing evidence must continue to refuse rather than selecting an ordinary driver.
- **Clipboard recovery itself is not certified by closure.** The existing `restore_locked` compares an explicit receipt with a clipboard snapshot (`src/input/ffi/clipboard.rs:265`, `:271`). The analogous unscoped schedule—first format publishes, a later SetClipboardData fails, then restoration encounters synthesized formats—belongs to the **SAME R4-2 receipt class** and predates this scoped rejection path. Comparing with the base shows that round 4 preserves that ordinary publication/failure/restoration sequence; it removes the new per-format scope-rejection trigger. Do not describe R4-2 as a repaired general rollback algorithm. No new unscoped recovery change was established.
- **No new dependency blocking Stop or release was established.** `prove_child` remains outside the pointer gate and ledger. The second sample proof runs on the input MTA, not the independent up sender. UIA's generation lock is shared with semantic operations, not Stop. Driver release bypasses scope (`src/driver_impl.rs:487`); native release bypasses the provider queue and pointer gate (`src/input/ffi/mod.rs:645`). Parent recovery retains its existing bounded 100 ms clipboard-restore attempt before up release (`src/worker/input.rs:285`, `:297`). No new lock, IPC acknowledgement or clipboard worker wait was added to that path. These are source observations, not measured timing guarantees.
- **Test reach is now stronger, but remains explicit.** `FakeInput::sample` calls the same production `sample_job::scoped` helper (`src/input/fake.rs:350`), so the new post-read failure test (`src/scope_regressions.rs:463`) exercises the actual read/exit decision, not a duplicated helper or manually assembled scope. It still substitutes `prove_delivery` and a fake text read for native `prove_child`/WM_GETTEXT; deleting the native adapter's wiring would leave it green. The clipboard refusal tests call the real parent receiver and child tracker (`src/worker/input.rs:514`, `:541`); their counting board establishes no stage entry, not real Win32 execution. No new test was found to bypass the particular production helper/receiver it now claims to cover.
