The ordinary task runner now refuses real/external launches before credential copying, fixture startup, cached preflight lookup, and credentialed tool preflight. Must-fix, category (a), before merge:

1. **[P1; A1; incomplete launch-boundary closure] The standalone fake-agent entry still starts an arbitrary backend on an environment declaration alone.** `gcu-eval/src/main.rs:167`, `:170`; `src/bin/fake_agent.rs:4`; `src/fake_agent.rs:154`, `:159`, `:172`, `:179`. The new guard exists only in `src/runner.rs:363`.

   Schedule: invoke `eval-fake-agent`, or `gcu-eval --gcu-eval-internal-fake-agent`, with `GCU_EVAL_BEHAVIOR=crash`, `GCU_BIN` pointing to an external wrapper, and `GCU_EVAL_ATTESTED=1`. No fixture files are needed for this behavior: `run` reaches `invoke` at `fake_agent.rs:44`. `backend_bin` accepts the declaration and `Command::status` executes the wrapper, inheriting the caller's environment. A wrapper can ignore the supplied `--driver fake` arguments and start a credentialed client. Neither `refuse_unsupported_launch` nor `supervise` runs; there is no provider receipt or `not_run` row. Setting `GCU_EVAL_BUILTIN_GCU=1` also authorizes the arbitrary path without verifying its identity. This route predates S6, but survives its promised removal of declaration-based external launches. The retained test explicitly requires the unsafe allowed branch to succeed (`tests/lockdown_r3.rs:208`, `:226`).

   Fix direction: keep these helper entries limited to verified offline artifacts/re-execution, with no `ATTESTED` or self-asserted `BUILTIN_GCU` exemption for arbitrary executables. Any external backend/client route must use the same provider admission policy. Replace that test's allowed branch with refusal assertions, and cover the standalone binary, hidden re-entry, and forged built-in marker using a harmless start sentinel. Keep positive controls for genuine fake artifacts. Passing fake-driver argv to an arbitrary wrapper is not confinement evidence.

2. **[P2; A2; new PR #162 telemetry/provenance regression] Halted tasks inherit another task's available telemetry and report unmeasured zero counts.** `gcu-eval/src/runner.rs:312`, `:316`, `:317`; `src/report.rs:73`, `:92`, `:95`.

   Schedule: use the existing `cleanup_failure_does_not_start_the_next_client` setup (`tests/lockdown_r3.rs:239`): two local fake tasks, scripted behavior, and injected failure of the first root removal. The first client writes the telemetry handshake and its logs are read. The run correctly stops after cleanup failure, but the second row replaces its fresh assurance with the first row's entire assurance, resetting only `client_started`. Its tool, side, state, and transcript telemetry therefore say `available` even though the second task never started or read any log. Its default metrics contain zeros, so task JSON emits `tool_calls: 0` and `unknown_calls: 0` instead of null. This is a current production-runner schedule, not a manually constructed report. The test checks the start bit and halt reason but misses the false telemetry.

   Fix direction: retain fresh per-task assurance on skipped rows. Propagate the run's halt cause separately from that task's observations; preserve any environment refusal as explicitly inherited stop evidence rather than copying all measurement state. Extend the existing production-runner test through `write_reports`: later rows must have unknown telemetry, null unmeasured call counts, no client start, and no newly claimed checks or cleanup operation.

3. **[P2; A3; offline gate defect] Attestation expiry is checked against time sampled before preparation, and never refreshed before client admission.** `gcu-eval/src/disposable.rs:412`, `:464`, `:467`, `:475`, `:476`, `:481`.

   Schedule through the existing offline supervisor: enter with `now=100`, valid bound evidence, and an attestation expiring at 101. Let `prepare` finish at 102, or let authenticity verification cross 101. All comparisons still use 100, so the credentialed-work callback runs with expired evidence. A successful teardown then leaves no refusal and permits `EnvironmentReport::complete()` to return true. The current tests only supply evidence already expired relative to a fixed 100 (`src/disposable/tests.rs:115`, `:202`); they cannot detect expiration during preparation/verification. There is no installed accepting runtime provider, so this does not presently reopen the ordinary real CLI path, but it contradicts the offline gate's validity guarantee.

   Fix direction: inject a clock rather than an entry-time scalar, authenticate the evidence, then check the relevant expiries using fresh time at the final admission boundary before invoking client work. Add deterministic clock advances inside preparation and verification; both must withhold the callback, produce `not_run` refusal evidence, and still tear down. Preserve the existing exclusive-expiry rule and a valid positive control.

Residuals, category (b), not additional merge blockers for the explicitly offline scope:

- **Passing-provider tests do not exercise the production client path.** `src/disposable/tests.rs:44` manufactures successful probe/attestation/cleanup state; `:115` calls the actual evaluator/supervisor, but its callback only pushes strings named `credentialed_tool_preflight` and `task_client`. Runtime use of `supervise` is the unavailable provider with a no-op callback (`src/disposable.rs:525`). These tests establish contract decisions and synchronous callback order, not actual credential seeding, client/preflight launch, timeout, or cancellation under an accepted provider. The logging-client integration tests do exercise the production refusal path. No accepting provider should be enabled on the strength of the event-vector tests.
- **Parent death proves the fake registry's cleanup, not whole-tree containment.** `src/disposable/tests.rs:459` starts an external fake supervisor; `:476` creates two direct workload children and retains their handles; `:488` calls fake teardown directly after owner-control EOF. Killing the owner bypasses its Drop, which is useful. However, neither child creates an unregistered descendant or performs `setsid`/`setpgid`, and this lifecycle does not go through `supervise`. The “detached-descendant” directory is storage, not an escaped process. Real Unix containment and Windows Job/VM reclamation remain `not_run`, as the README states. `src/proc.rs:7`, `:90`, `:92` retains the known process-group/Windows limitations; `src/prep.rs:489` still kills/waits only the fixture leader. Do not promote either local mechanism to a whole-tree receipt.
- **Native and external guarantees remain unproved.** Real signature verification, pinned trust roots, GUI/permissions/Stop readiness, filesystem/IPC confinement, actual gateway enforcement, and destruction on all three platforms are absent. The sentinel broker and seven loopback route classes (`src/disposable/tests.rs:294`, `:319`) are controlled evidence-handling simulations, not OS or network isolation tests. S1/S3's accepted native-delivery, helper, cache-retirement, and platform residuals are not reopened or treated as solved by S6.
- **Unavailable cleanup is a no-resource result.** `src/disposable.rs:508` emits passed cleanup fields with no prepared binding, while every guarantee and ACK remains unknown and the refusal remains `provider_unavailable`. This cannot make the attempt complete. It must not be read as measured VM/tree destruction. Likewise, oracle self-test and platform skips occur before the new gate (`src/runner.rs:351`, `:354`) and can have no environment report; the README's “each task report” wording is broader than that wiring.
