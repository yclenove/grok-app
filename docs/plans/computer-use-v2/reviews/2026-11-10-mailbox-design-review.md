Verdict: **ACCEPT-AFTER-FIXES**

Independent design review of ADR 0019 on `cu2/design-mailbox`, commit `e1cc8a4df9c1afbcc9d0d1e604d43b3c86910f49` (2026-11-10). I did not author the proposal. Findings concern the design and its integration obligations; none is a claim of a reproduced macOS defect.

Reviewed ADR 0019; ADR 0018, including its budgets, fault table, egress requirements, measured facts and H1 decision; ADR 0017, including S3/S4/S12; acceptance matrix §8; and `guest.rs`, all `machine/*.rs`, and supporting budgets/parsers/runner interfaces. References below are relative to `computer-use/` unless explicitly marked repo root. Line numbers refer to the reviewed commit.

The owner decisions stand: production control uses no IP channel; Softnet blocks `0.0.0.0/0`, including the gateway, with only the approved model endpoint `/32`; there is no host guard/pf rule; the per-attempt mailbox on a dedicated capacity-limited volume is the sole shared-directory exception. This report does not authorize host operations or real evaluation. The architecture does not need a new lifecycle manager. The must-fix items are publication identity, destructive-operation identity, the synchronous scheduling/deadline contract, superseded lease replies, and the probe dependency cycle.

1. **Must-fix — Exclusive creation does not protect the temporary name through publication.** ADR 0019 §3, lines 103–107.

   **Principle:** Publish the object the host created and checked; a guest-writable pathname is not an object capability.

   **Failure scenario:** The host exclusively creates `host-write/lease.msg.tmp`, checks its FD and writes its bounded frame. The guest renames/unlinks that entry and puts a different regular file or symlink at the same name. The host closes its original FD and `renameat` publishes the replacement as `lease.msg`. A pre-existing link at the initial create is correctly rejected by `O_EXCL`; this later substitution is a different race. `renameat` itself does not follow the symlink or truncate its target, so this is not an established outside-volume write. It does invalidate the stated checked-object publication procedure. Merely adding another `fstatat` before rename leaves another check/use gap.

   **Minimal fix:** Stage host publications in an unexported, host-controlled directory on the same dedicated volume, using its verified parent FD; retain and check the created FD through write/fsync and publish by `renameat` from that protected source parent. Verify the destination directory identity and define replacement of the previous fixed slot explicitly. The export remains only `mailbox`; staging is not another shared directory. Guest replies remain untrusted and must pass the existing reader checks even after publication. Add the source-name substitution race to C3 and M3. Also spell out that FSID is obtained from the opened object, e.g. `fstatfs(fd)`, while `fstat` supplies `st_dev`; pathname-based filesystem queries do not replace those checks.

2. **Must-fix — Destructive identity is checked before dispatch, but the fixed device pathname can be retargeted before the effect.** ADR 0019 §2, lines 57, 63, 67–74.

   **Principle:** Authority to destroy an attachment must survive until the destructive operation uses it.

   **Failure scenario:** Recovery positively maps the recorded image inode and volume UUID to `/dev/diskN`. Between that readback and `hdiutil detach [-force] /dev/diskN`, another host disk operation detaches the original and attaches an unrelated image that receives that number. The argv now addresses the unrelated attachment. Rechecking before each command reduces this window but cannot atomically bind the external command to the checked attachment. This requires a competing host operation; it is not a claimed ability of the sandboxed model. The same distinction matters when describing a pathname identity check immediately before unlink.

   **Minimal fix:** State the trusted-host mutation/exclusivity assumption under which these pathname commands are safe, including competing attach/detach and path replacement, and how the approved experiment enforces that assumption. The eval cleanup lock alone does not exclude other host disk tools. If that exclusion cannot be established, require an attachment-specific operation whose identity remains bound through the effect, or quarantine instead of issuing destructive argv. Do not claim that repeated `diskutil` queries alone close this race. Keep whole-image device mapping, fresh UUID/inode checks, and the rule that unresolved identity never authorizes force or unlink. No global firewall, daemon, or broad disk cleanup is needed to express this boundary.

3. **Should-fix — Persist the identities of the directories and distinguish the covered mountpoint from the mounted root.** ADR 0019 §2, lines 31, 37–42, 67–72; §3, line 105.

   **Principle:** Creation intent permits reconciliation, not ownership of whatever later occupies the intended name.

   **Failure scenario:** A crash occurs after creating `M` or a seed entry but before its identity is recorded. Recovery has an intent and a fixed name, then interprets “registered fixed entries” as permission to remove the object currently there. Alternatively, it records only the mounted root's inode and later compares it to the different underlying directory exposed by detach. The reader paragraph implies recorded directory identities, but the resource table explicitly records parents and the image inode without enumerating these child identities.

   **Minimal fix:** List the persisted parent/child identities for A, the underlying empty M, S and each fixed seed entry, separately from the mounted root's filesystem identity. Apply verified-parent-FD, no-follow identity checks to each unlink/rmdir, and require mounted-anywhere absence before image unlink. Missing child identity, replacement or an unexpected entry means quarantine; no recursive fallback. Explicitly cover lost mkdir replies and replacement directories in M5. An intention-only orphan may remain quarantined indefinitely; that is a safe outcome.

4. **Must-fix — “Slice slow commands” needs a concrete caller-driven contract, including operation deadlines that survive pending polls.** ADR 0019 §3, lines 119–125; §6, lines 172–175. Code: `crates/gcu-eval/src/disposable/tart/machine/steps.rs:289`, `:333`, `:361`, `:437`, `:465`; `machine/io.rs:117`, `:134`, `:220`; `machine/cleanup.rs:99`.

   **Principle:** One caller can preserve liveness only if every wait yields to it, and an operation keeps its original deadline.

   **Failure scenario:** A real synchronous `runner.stop` spends four seconds waiting for its child while the provider cannot consume the external owner's heartbeats. Its old owner lease expires and the subsequent delete must enter `Suspended`, despite a live owner. During preparation, `isolate` can similarly run 16 probes without returning to the caller for guest renewal. Separately, `run` returns accepted quickly and inventory is polled with fresh query deadlines: `io.rs` currently has no Task aggregate, so the polls can outlive the original task budget unless a saved operation end is supplied. Giving every poll a fresh login/bootstrap/probe budget has the same defect.

   **Minimal fix:** Make M4 cover the entire caller loop: reserve/preparation owner liveness, start/inventory/probes, bootstrap/login/run, revoke, stop, delete, detach, queries and sealing. Begin each subprocess once, retain its handle in the existing owner, and poll bounded slices while servicing owner proofs and Stop; guest renewal runs only where still applicable. Preserve the original phase/operation and aggregate ends across all polls through the single `io.rs` dispatch path. Do not restart operations on pending. Specify a total scheduling bound between liveness/Stop checks, not just “each IO ≤100ms”; a list of individually bounded slices can still consume seconds. Show offline traces with slow queries/probes/cleanup and expiry during a slice, including kill/reap, with no new thread or observer.

   The numerical caps themselves are consistent: volume preparation shares the 120s start allowance; prep ≤10min; run ≤min(task,15min); query ≤5s; probe ≤2s/group ≤60s; bootstrap/ACK ≤5s; login ≤5min. Cleanup's 10+20+20+10 seconds remains 60s, with delete/detach/unlink sharing the 20s deletion stage. Sub-budgets are caps and need not all fit at their maxima; when the enclosing deadline is exhausted, stop and quarantine. Those caps must remain absolute across accepted/pending transitions.

5. **Must-fix — Define how superseded lease acknowledgements are distinguished from wrong-request frames.** ADR 0019 §3, lines 91, 100, 109, 113.

   **Principle:** An intentionally overwritable liveness slot must tolerate its own delayed valid traffic without renewing from it.

   **Failure scenario:** Host publishes lease 1, then lease 2 before reply 1 becomes visible, as the lease overwrite exception permits. The next read sees reply 1, which the host has never consumed. It is neither the current request nor a previously processed duplicate. The current wording also says wrong-request replies are protocol violations, so ordinary visibility lag can permanently fail an otherwise valid attempt. “Previously processed old slots are harmless” does not cover this case.

   **Minimal fix:** Specify a bounded rule for obsolete acknowledgements of leases actually issued in this boot/attempt. Ignore such replies without extending any deadline; reject future/never-issued or inconsistent replies. Alternatively serialize lease acknowledgements and make the measured timing gate prove that this still meets publication cadence. Specify the guest sample's units, boot binding and association with an actual issued inventory sample, with overflow/future-sample rejection. M3/M4 must include overwritten requests, skipped observations and delayed acknowledgements.

   The `g+2s` idea is sound without comparing wall clocks: a valid echoed sample was generated before the host could use it, so delayed delivery consumes its remaining lifetime instead of creating a fresh lifetime. Reserve the last second for scheduling/revoke/whole-tree termination, reject after the old deadline, and use a guest monotonic clock with explicitly measured pause/suspend behavior. At approximately 1s visibility latency in both directions, sample-to-lease delivery can consume the entire two-second grant; a one-second host publish period does not rescue that. Measure sample age at guest acceptance, gaps between accepted grants and termination completion under load. C1's round-trip gate must block implementation if this fails; do not extend the lease or Stop constants. The earlier observation of “about 1s” is insufficient evidence of viability.

6. **Should-fix — The unchanged trait is credible, but the codec-to-machine pending contract must be explicit for every operation.** ADR 0019 §3, lines 95–101, 109, 117–119; §6, lines 172–173. Code: `crates/gcu-eval/src/disposable/tart/guest.rs:52`; `machine/steps.rs:302`, `:311`, `:346`, `:370`, `:444`; `machine/io.rs:245`; `machine/cleanup.rs:81`.

   **Principle:** Transport progress and operation completion have different meanings.

   **Failure scenario:** M3 returns an empty slot as `CallError`, so `phase_out` marks an expected first-read pending state as permanent failure. Or only login/run parsing is changed: bootstrap still requires an immediate ACK, probes still require immediate `passed/failed/unknown`, and revoke/lease treat any successful body as confirmation. An accepted revoke could then be recorded as a completed drain. Current bootstrap, login and run parsers all consume immediate final bodies, not only the latter two.

   **Minimal fix:** Keep the seven `GuestChannel` methods and version 1. `BoundedOutput` can carry a closed pending/accepted/terminal vocabulary; adapter-private state can retain the current request and sequence. Document how repeated polls avoid re-dispatch, which methods complete via inventory, and how completion remains bound to the original request. Define exact per-operation status/payload schemas and terminal retention until consumption, including startup inventory's unknown boot. M3 owns wire/open/publish behavior; M4 owns pending state, renewal and completion/deadline semantics. Accepted does not create a score, native ACK, cleanup proof or admission capability. No trait expansion is required by the inspected interface.

7. **Must-fix — S11-0c currently depends on the supervisor whose feasibility it is meant to establish.** ADR 0019 §4, lines 129–137; §5, lines 141–143, 153; §6, lines 171, 176–178.

   **Principle:** A mechanics probe should not require a later security implementation to produce its evidence.

   **Failure scenario:** M2 cannot run because its launcher must not bypass S11e, while M7 later implements the supervisor/golden/sandbox. In particular, C7 requires the supervisor to stop a tree within the lease bound; a simple trusted file probe cannot demonstrate that property. C4/C8 also need a defined way to execute as two test principals; installing an ordinary-user launcher alone does not grant arbitrary chown or a second UID.

   **Minimal fix:** Define M2's minimum trusted deterministic probe entry independently of full S11e. Keep C7's detach/cache/underlying-directory measurements in M2, but defer autonomous expiry/tree termination to M7/M9 with a harmless substitute tree. Likewise separate file latency in C1 from final supervisor liveness acceptance. Arrange two prepared unprivileged test identities, or record permission-denied results and defer the unavailable subcase; do not invent guest sudo. This removes the dependency cycle while keeping every security claim unverified until the appropriate card passes.

8. **Should-fix — Permit SSH for the pure mechanics probe scope, with an explicit experimental network exception and limited evidentiary value.** ADR 0019 §5, line 141; §6, line 171. Related measured facts: ADR 0018 §13, lines 263–282, and §14, lines 292–299.

   **Recommendation to the controller:** Yes. Driving the pure file/volume parts of C1–C10 over key-only SSH on a DEFAULT-Softnet disposable clone is simpler and acceptable as a separately described, trusted, model-free laboratory experiment. Existing measurements already establish that this SSH route works. It avoids building the production autonomous supervisor merely to measure rename, fsync, ownership and hdiutil behavior. Keep block-all plus the autonomous supervisor for M7/M9 and the production path. C7's autonomous shutdown assertion is not a pure mechanics result and cannot be accepted from an SSH-dependent test.

   **Principle and precise trade-off:** SSH key authentication protects the login; it does not restrict guest egress. Default networking was measured to expose host gateway ports 22/53/5900/445/7000, and permits more network access than the production policy. A trusted test program, compromised guest service or accidental network command can affect the host before the clone is discarded. Discarding the clone does not undo those effects. This exception therefore relies on a vetted no-personal-data/no-login image and reviewed deterministic code, and produces no evidence of host-network isolation, block-all autonomy, S11e sandboxing or real-eval eligibility. It changes the experiment's guest policy; it requires no host network/firewall change and is not a proposal to reopen production H1.

   **Failure scenario:** A generic remote shell, startup script or forwarded host agent becomes reachable in a test described as having “no host-network access,” or an SSH-driven successful C7 is later counted as proof that control loss causes autonomous termination.

   **Minimal fix:** Replace that absolute description with the explicit exception before conducting it, within the owner's concrete probe authorization. Pin the guest SSH host key and exact clone/IP/boot mapping; use a dedicated limited test identity and disposable authentication material, with the private key kept on the host. Disable agent/X11/port forwarding, inherited SSH configuration/proxy commands, interactive auth and automatic host-key acceptance; use fixed reviewed probe commands, bounded output, per-command deadlines and outer kill/reap. No model/eval credentials, personal mounts, external downloads or intentional guest network requests. SSH is only an experimental driver and must not supply the lease, expected file bytes or authoritative mount/cleanup result being measured. Guest/host-local timestamps and host readback collect those results. Results must be marked DEFAULT-network/mechanics-only; repeat transport/liveness-dependent measurements under block-all in M7/M9. If this additional guest reachability is unacceptable to the owner, use the prepared launcher path and accept its setup cost; do not quietly weaken the production filter.

9. **Should-fix — `-srcfolder` does not establish a safe first-mount story merely because its source contains markers.** ADR 0019 §2, lines 29, 37, 50–61; §5, lines 150, 156.

   **Principle:** Tool-internal mounts and copies are effects too; distinguish no-guest-content preparation from exporting hostile content.

   **Failure scenario:** The selected `hdiutil create -srcfolder` implementation mounts intermediate storage to populate the filesystem, before the marker files have been copied and outside the explicitly constrained attach at M. The later mount-flags and indexing readbacks cannot prove what happened during that earlier mount. This is a must-measure behavior on macOS 27, not an assertion that that implementation definitely does so. At this stage S is synthetic, so an internal preparation mount is not automatically a guest-code execution exposure, but it contradicts an unqualified “flags from the first mount” claim.

   **Minimal fix:** Delete the claim that pre-populating S proves marker presence before any mount. Measure create's intermediate devices/mounts, scratch storage, copying of root markers, exact resulting root layout, permissions and service activity. State precisely that hostile bytes are exported only after the controlled mount and readbacks pass. If the stronger all-mounts requirement is necessary and create cannot satisfy it, reject this argv recipe rather than silently treating a later attach as the first mount. HFSX/SPARSE/64MiB/layout NONE is a reasonable candidate for POSIX semantics and a small fixed filesystem, conditional on these measurements; no alternative filesystem mechanism is needed pre-emptively.

10. **Should-fix — Turn the argv table into a no-elevation measurement checklist, rather than assuming user-owned resources make all operations unprivileged.** ADR 0019 §2, lines 44–63; §5, lines 150–152, 156.

    **Principle:** Unsupported options, authorization prompts and unreadable evidence are measured blockers, not reasons to add sudo.

    **Failure scenario:** `tmutil addexclusion` on the selected item kind needs permissions/privacy access the eval account lacks, or a DiskImages/Disk Arbitration operation invokes authorization. The command hangs awaiting a GUI prompt or reports an exclusion that does not cover the intended image/mounted filesystem. Alternatively, a mount option is ignored or a label is mistaken for UUID identity. The ADR correctly says everything is unverified, but does not give the operator a precise privilege/semantics inventory.

    **Minimal fix:** Measure, as the actual eval user and without elevation or interactive authorization:

    - `hdiutil create`: exact support and combined semantics of `-fs HFSX`, `-type SPARSE`, `-size 64m`, `-layout NONE`, `-srcfolder`; non-journaled result, suffix/path behavior, root contents, mode and all temporary resources.
    - `hdiutil attach`: actual support and effect of `-owners on`, `-mountOptions rw,nosuid,noexec,nodev`, `-nobrowse`, `-noautoopen`, `-mountpoint`, and plist fields; reject silently missing restrictions. Measure user authority for normal and forced detach and the whole-device selection.
    - `hdiutil imageinfo/info`, `diskutil info -plist`, `mount` and `mdutil -s`: these are inspection operations, not a proposal to run privileged `mount`, `diskutil` mutations or `mdutil -i off`. Verify available fields, reliable bounded parsing and whether the eval user can obtain the required observations on macOS 27.
    - `tmutil addexclusion/isexcluded`: determine exact behavior on A, I and M. Owner-set sticky path/file exclusions and fixed-path/volume exclusions have different semantics and potentially different privilege requirements; do not substitute `-p` or `-v` as an unreviewed fix. Measure required root/Full Disk Access/authorization behavior and whether excluding the underlying mountpoint survives the mount as intended. A successful invocation alone is insufficient.
    - `.metadata_never_index` and `.fseventsd/no_log`: measure recognition and actual effects; they are not access-control primitives. Specify an observation method available without sudo for the claimed mds/FSEvents/backup evidence. An idle observation window with no backup job is not proof that backup exclusion works.

    None of these macOS 27 option/privilege details was verified in this review. Preserve no sudo, no interactive fallback, no global indexing changes and quarantine on an unconfirmed operation. The proposed read-only queries and image-local mutations are otherwise plausibly minimal. Normal detach ≤5s, one force ≤5s only after the stop barrier, and **never unlink a still-mounted or possibly still-attached image** are correct policies.

11. **Should-fix — Make C1–C10 workloads and negative observations executable within their stated bounds.** ADR 0019 §2, line 29; §5, lines 143–156.

    **Principle:** A finite probe needs a work bound, a time bound and an observable pass condition; reaching the watchdog is not automatically a filesystem failure.

    **Failure scenario:** C1 runs 100 sequential publications at the previously observed roughly one-second visibility and exceeds its 60s workload cap before it can characterize latency. C5 tries every crash point, C9 fills many tiny files, or C10 waits for system backup activity in the same 60s, producing ambiguous incomplete results. C3's broad adversarial list can also miss the host-write race while reporting the whole row passed.

    **Minimal fix:** Split subcases into independently bounded attempts or give explicit finite iteration/file/operation caps and mark an unfinished subcase unknown. For C1, allow a bounded mechanics sample to report slow latency separately from the stricter production lease gate; report sample count, maxima and measurement points, not only p99 from a tiny sample. C3 must explicitly cover preplanted write tmp links, tmp substitution after open, precheck/open regular-to-FIFO/device swaps, directory replacement, rename-into-place, cross-export/outside-volume hardlink attempts and file mutation/replacement during repeated reads. Use only synthetic canaries on every side; a failed hardlink syscall is an observation, not permission to relax checks. C5 must include lost mkdir/create/attach replies, detach success before acknowledgement, a replaced image inode and reused device identifiers.

    The ≤80MiB backing condition is testable: record both image `st_size` and allocated blocks with an explicit unit conversion, during bounded adversarial fill/sparse/truncate/churn subcases as well as after completion; include create-time scratch resources and cleanup held-FD cases. A few observed peaks are evidence for the selected image format, not a universal proof. A sparse image on an APFS host also does not eliminate host APFS COW/snapshot retention; clarify that the bound concerns the live image and dedicated filesystem, and separately account for prohibited backup/snapshot copies. C9's “no other directory growth” must exclude ordinary bounded ledger/receipt accounting and define the storage effects it actually observes. If the required backing limit or no-index/no-backup evidence cannot be established without prohibited host operations, this recipe remains blocked.

12. **Nit — Resolve card ownership and remove claims stronger than the evidence.** ADR 0019 §3, line 121; §6, lines 172–173; §2, lines 29, 50; §5, line 141.

    **Principle:** Put one obligation in one card and distinguish measured facts, requirements and hypotheses.

    **Failure scenario:** An implementer places owner/guest lease separation in M3 because line 121 calls it an M3 gate, while M4's owner assumes it is already covered; neither reviews the complete scheduling trace. Another implementer treats “avoids APFS COW complexity” or pre-installed marker behavior as a measured guarantee.

    **Minimal fix:** Assign codec/open/publication to M3 and the complete pending/lease/scheduling/deadline machine to M4 consistently. Keep one concise budget table and one destructive-resource identity checklist instead of repeating their prose. Remove the speculative first-mount-marker guarantee and the implication that an HFSX image eliminates its host backing filesystem's COW/snapshot behavior. Replace “no host-network access” if the recommended probe exception is adopted. Keep the exact no-follow procedure, irreversible expiry, quarantine rules and native-evidence gates; those details are necessary, not density to delete.

ADR 0019 §6 correctly preserves ADR 0018 §5's LAN/metadata/DNS/IPv6/UDP/QUIC and endpoint-service-boundary requirements despite removing the host guard. An IPv4 `/32` allow rule is not by itself proof of TCP-only egress, denied IPv6 or rejection counters. If S11c cannot produce those proofs under the owner-selected policy, admission remains closed; neither the SSH experiment nor this design review can substitute for acceptance matrix §8. Stop stays at 100ms latch, 500ms release, 5s native and 4750ms driver with the existing platform retry limits; no mailbox deadline enlarges those bounds, and no recovery path automatically resumes.
