Verdict: **MERGE-AFTER-FIXES**

Independent static review of `cu2/tart-s11a`, commit `a9ad8b96` against `7ccadb5a`. Findings 1–3 are merge blockers for the offline contract. The change does not open admission or implement a provider. This review accepts the explicitly limited S11a scope: interfaces and fakes, with H1/H2 unresolved; it does not require S11-0 results, a state machine, a transport, or a host guard in this card. Earlier S1–S12 decisions are not reopened.

Read ADR 0018, including §§1–3, 5, 8, 10–11; the acceptance matrix; `boundary.rs`; `disposable.rs`; all ten Tart source files; the harness-free test; and the complete change against the base. Code references below are relative to `computer-use/crates/gcu-eval/`; bare Tart filenames in the result bullets abbreviate `src/disposable/tart/`. Documentation references are repository-relative. This was source inspection only: Rust compilation/tests and mutation execution were **NOT_RUN**. No network or real VM/network operations were performed. Only this review file was written; no commit was made.

1. **must-fix — Clone ignores the reservation's absolute deadline.** `src/disposable/tart/runner.rs:120`, `src/disposable/tart/runner.rs:130`; binding stored at `src/disposable/tart/ledger.rs:232`.

   **Principle:** A per-call budget cannot extend the absolute attempt budget recorded before allocation (ADR 0018 §2).

   **Failure scenario:** At fake time zero, reserve a clone with an `AttemptDeadline` one second away and retain its permit. Advance the shared clock to that exclusive deadline. Queue success and call `clone_vm` with a fresh 60-second `CloneDeadline`. The fake returns success and records a clone: it reads only `permit.clone_id()`, then tests the new call deadline. The permit's absolute deadline is discarded. A still-live permit with only one second remaining can likewise be passed with a 60-second call deadline. Thus the offline runner models allocation after the attempt has expired, or a call extending beyond its hard deadline. The existing expired-attempt test covers `reserve`, not subsequent use of a permit.

   **Minimal fix:** Specify that cloning uses `min(call_deadline, permit.absolute_deadline())`, and apply that bound in the fake before dispatch. At or after the absolute deadline, consume the permit but return expiry without consuming the scripted reply. Record the effective deadline so traces can assert it. Add the exact-boundary rejection and shorter-parent-deadline cases. This requires no state machine or real adapter.

2. **must-fix — The public IPv4 validator admits non-global special-use addresses.** `src/disposable/tart/policy.rs:89`, `src/disposable/tart/policy.rs:120`; claimed contract at `src/disposable/tart/policy.rs:50` and `computer-use/docs/adr/0018-tart-disposable-provider.md:221`.

   **Principle:** Endpoint allow entries must satisfy the stated public-address restriction before they become a Softnet policy description (ADR 0018 §5).

   **Failure scenario:** `SoftnetFlags::try_new(&[Ipv4Addr::new(192, 0, 0, 1)])` succeeds. That address belongs to the non-global IPv4 Service Continuity prefix; `192.0.0.8` and the NAT64/DNS64 discovery addresses `192.0.0.170`/`.171` also pass. None matches the current exclusions. Consequently the validated type can contain a non-public endpoint while its documentation promises the opposite. This is a validation defect in the offline type; it is not evidence that any real egress was allowed.

   **Minimal fix:** Complete the special-use classification with a small, explicit table or equivalent predicates, conservatively rejecting non-global/reserved entries. If admitting exceptions within `192.0.0.0/24`, distinguish the globally reachable exceptions rather than treating that entire /24 as public. Add representative addresses and boundaries, including the counterexamples above. Keep owner approval, actual gateway exclusion, and enforcement/probes as separate S11c obligations; address syntax cannot prove them.

3. **must-fix — The watchdog silently disappears on non-Unix builds.** `tests/tart_offline.rs:965`; test registered without a platform restriction at `Cargo.toml:64`.

   **Principle:** Every supported execution of the integration test needs an independent wall-clock bound; a blocked implementation cannot be allowed to block its own timeout (ADR 0018 §8).

   **Failure scenario:** On Windows, both watchdog functions are empty, but the same 16 checks run. A regression introducing an infinite loop or blocked wait hangs the test process indefinitely. `harness = false` provides no timeout. On Unix, `alarm(30)` can terminate the current process under the assumed signal disposition, but it is a self-alarm rather than the specified external kill/reap owner. There is no parent supervisor in this target.

   **Minimal fix:** Use a harness-owned child process and monotonic parent deadline, kill/reap it within the ADR ceiling, and test the wrapper with a deliberately non-returning child mode. Reuse the existing bounded-child approach where practical; do not add production observer threads. An explicit Unix-only restriction would avoid the unguarded Windows execution, but would not replace the required external watchdog. The current fake methods themselves contain no lock or wait, so this finding concerns the promised regression containment, not an observed hang.

4. **should-fix — Security properties named by the tests are not all mutation-protected.** `tests/tart_offline.rs:408`, `tests/tart_offline.rs:773`, `tests/tart_offline.rs:842`; `src/boundary.rs:367`.

   **Principle:** Tests should fail when the invariant they advertise is removed. A source substring check is only a guard for the spellings it recognizes.

   **Three concrete implementation mutations the inspected tests would not catch** (static predictions; no source was mutated):

   - Add `Clone` to `ClonePermit`'s derive at `src/disposable/tart/ledger.rs:89`. The “single use” test drops a permit and checks duplicate reservations; it never tests whether an existing permit can be duplicated. Neither source scan rejects that derive. All existing uses remain valid, but a caller can now clone twice from one reservation.
   - In `FakeGuestChannel::record` at `src/disposable/tart/guest.rs:117`, replace `self.clock.now()` with `MonoInstant::EPOCH`. The guest test performs only successful calls at time zero. Tart runner expiry tests exercise the shared dispatcher through the Tart implementation, so they still pass while the guest implementation ignores its actual clock and accepts stale deadlines.
   - Add a grouped import `use std::{ffi::OsStr, process::Command as Process};` to `runner.rs`, then add `let _ = Process::new(OsStr::new("sh"));` to `FakeTartRunner::new`. This constructs a prohibited process builder without starting it. Neither scan sees `Command::new`, `std::process`, `tokio::process`, or an `AdmittedLaunch` token in those additions. Existing behavior tests do not observe the discarded builder. The normal grouped-import spelling avoids relying on exotic whitespace or a shell escape.

   **Minimal fix:** Add a compile-fail assertion for permit duplication/construction and a guest expiry test that advances the shared clock and verifies the queued reply remains available. Give the source guard negative fixtures for grouped/aliased imports and cover those forms structurally or with targeted import checks. Do not describe the present substring scan as a proof against arbitrary Rust aliases. Findings 1–2 also need their direct counterexample tests.

5. **should-fix — Debug formatting exports raw reply bytes.** `src/disposable/tart/output.rs:46`; derived error formatting at `src/disposable/tart/output.rs:100`.

   **Principle:** Untrusted guest/runner payloads must not become ordinary diagnostics or receipt content (ADR 0018 §7).

   **Failure scenario:** Construct a bounded malformed reply beginning with a device code, token fragment, or sensitive guest content, then format its `CallError` with `{:?}`. The derived formatter invokes `BoundedOutput::fmt`, which prints the first eight bytes as reversible numeric values. Limiting their number does not sanitize them. This behavior is present without any real transport, although no production logging caller was found in this slice.

   **Minimal fix:** Delete the prefix field from `BoundedOutput`'s Debug output; retain only length. A short test should assert that formatting a distinctive payload exposes neither its text nor its byte sequence. No logging framework or new redaction mechanism is needed.

6. **should-fix — Expiry at entry is described as cancellation, despite an immutable synchronous call.** `src/disposable/tart/runner.rs:26`, `src/disposable/tart/guest.rs:48`, `src/disposable/tart/guest.rs:67`, `src/disposable/tart/guest.rs:70`.

   **Principle:** Long operations must leave the caller able to renew leases and handle Stop/revoke in the existing bounded loop (ADR 0018 §2); entry-time refusal is a different property from cancelling an operation already in progress.

   **Failure scenario:** A future guest implementation interprets synchronous `run` as waiting for task completion and holds `&mut self` for its valid 900-second deadline, or `login` for 300 seconds. The caller cannot issue `lease` or `revoke` on that same channel while it waits. The passed deadline is a copied value and cannot be made “already due” after entry. Such an implementation satisfies the written return-by-deadline requirement while starving the ≤1-second lease schedule and crossing the ≤3-second guest liveness limit. The immediate fake cannot reveal this incompatibility.

   **Minimal fix:** Delete the claim that an already-due deadline provides general cancellation; document it as rejection before dispatch. Leave completion-wait semantics to S11b, explicitly requiring bounded polling/yielding around long operations, or specify that the fixed operations acknowledge initiation rather than synchronously waiting for completion. Do not solve this in S11a by selecting a transport, adding background workers, or implementing the state machine.

The remaining requested checks have these results:

- **Capability and argument boundary:** `TartCommand` has only closed variants and restricted `CloneId`, `GoldenImage`, and `SoftnetFlags` fields (`command.rs:10`). There is no path, free-form flag, argv vector, shell, process builder, or launch-capability constructor in the inspected implementation. Identity fields are private and have no serde bypass. Validation rejects empty/>64-byte values, slashes/backslashes, dots, whitespace, leading/trailing separators, `--` anywhere, and all non-ASCII characters, including Unicode confusables (`identity.rs:36`). Golden-name checks are case-insensitive and reject names beginning with `golden` or the complete fixed golden name. A truncated golden prefix such as `macos-s2-eva` is representable, but remains a different exact token; there is no prefix lookup that maps it to golden. Softnet has only the fixed block-all rule and 1–16 unique IPv4 /32 entries, with the classification defect in finding 2. A future runner cannot receive arbitrary argv through these method arguments; it must still map them to fixed individual arguments and construct processes only through admission.

- **Deadline and output boundary:** Every Tart, guest, and ledger operation takes a non-optional deadline. Deadline types have no Default/serde/public fields, reject zero and above-cap durations, and use checked conversion/addition; overflow is rejected rather than saturated into a distant deadline (`deadline.rs:32`, `deadline.rs:55`). `FakeClock` cannot rewind and shares updates through `Rc<Cell<_>>`; no wall clock is used. `HostClock` is a nonblocking monotonic-clock contract, not a real clock implementation. `MonoInstant::from_nanos` is public, so same-clock provenance remains a trusted-caller obligation: a caller can base a five-second deadline on an arbitrary future instant. Consumers must not infer a physical five-second bound from the type alone. Finding 1 covers the absolute attempt bound actually available to cloning. Successful, failed, and malformed bodies all contain private-field `BoundedOutput`, capped at 1 MiB (`output.rs:20`); overlong scripted outcomes retain no body. This constrains returned length, not how much a future reader allocates before constructing the value; real adapters must also bound collection while reading. No input-reachable `unwrap`, unchecked arithmetic overflow, or indexing panic was found. Array slices in policy are bounded by the checked ≤16 length; ledger indices come from the same unchanged vector; Debug's current prefix index is length-clamped. No reply parser is implemented yet.

- **Ledger ordering, identity, and locks:** In safe Rust, the only current permit constructor follows the row insertion (`ledger.rs:225`, `ledger.rs:232`); `clone_vm` consumes it by value. It is not Clone/Copy/Default/serde and has no public constructor. This proves ordering within the memory fake, not durable ownership. Queries, duplicate checks, appends, and seals compare complete case-sensitive IDs. Duplicate reserve and second seal refuse without changing the row; seal is not an idempotent-success API, and append can repeat facts. There is no implemented cleanup state machine or authoritative deletion test. Golden cannot be represented as a clone ID, but a syntactically valid foreign name can be reserved, started, stopped, or deleted by the fakes: runner methods other than clone explicitly do not check ownership (`runner.rs:22`). A reservation of a name must never establish ownership of an already-existing VM. The fake stores no VM/config/boot instance identity, is not persistent, and takes no lock. S11b still must prove collision handling, exact live-instance matching, durable pre-clone registration, authoritative absence, crash recovery, and idempotent cleanup. There is currently no IO or wait under a lock because there are no locks. The real ledger's try-lock/deadline/no-IO-under-lock requirements remain unproved; the fake's speed is not lock or crash evidence.

- **Guest transport boundary:** The input operations are exactly inventory/probe/bootstrap/login/run/lease/revoke; the only payloads are a closed `Probe` and a nonzero lease sequence. No arbitrary path, shell, forwarding, address, or raw request bytes exist. Raw bounded reply bytes are response data, not a guest execution interface. Version 1 does not commit to SSH, virtio, a shared folder, or a gateway. Per-session authentication/binding, replay rejection, actual deadline enforcement, and lease scheduling are future implementation obligations; nonzero sequence syntax alone does not prove them. H1 remains unresolved. Finding 6 addresses the synchronous waiting/cancellation ambiguity without choosing a transport.

- **Public API and evidence:** Public fakes are acceptable for this expressly offline slice under ADR §§8/11; blanket `cfg(test)` gating is not needed to preserve today's closed admission. They are named as fakes, do not implement an accepting `DisposableProvider`/verifier, and cannot manufacture `AdmittedLaunch` or a verified session. No new Tart receipt, permit, manifest, or policy is serde-deserializable. However, `FakeLedger::reserve` is publicly callable and returns the same `ClonePermit` required by the runner, and the permit is not bound to a particular ledger or runner. A future production adapter must not accept possession of that token as proof of a durable reservation: gate the fake mint behind test support or require an independent trusted-ledger/instance check before real allocation. That is a condition for later linking, not an existing executable bypass. Existing serde evidence in `disposable.rs` remains data and still cannot open admission. `accepting_provider_linked` and `scoped_provider_ack` remain private loads of function-local, never-written false atomics (`boundary.rs:108`, `boundary.rs:116`); their implementation and admission constants/functions are unchanged.

- **Source-scan coverage and test reliability:** The walker still visits the same `src` and `tests` trees, and the prior non-Tart command condition and both mint checks remain intact. The new Tart branch deliberately scans `tests.rs`/`*_tests.rs` inside that directory instead of applying the old filename exemption. It adds coverage; it does not remove prior hits. It can produce false positives from comments/string literals mentioning forbidden tokens, including in a legitimate Tart test. It has the alias false negative in finding 4. The boundary walker's silent IO-error skips are inherited; `tart_files > 0` proves at least one visit, not completeness. The harness's separate walker fails on traversal/read errors. Tests have private clocks/queues, no sleeps, no network, and no shared mutable global state besides the Unix process alarm. No ordinary timing race or parallel-test flake was found. The 30-second suite ceiling can fail under extreme scheduling delay, as any hard watchdog can; non-Unix hang containment is missing as in finding 3. Do not claim the current tests prove durable ordering, real timeout cancellation, VM destruction, or network enforcement.

- **Documentation:** ADR 0018 §11 and ADR 0017's S11 row (`computer-use/docs/adr/0017-real-eval-fixture-scope.md:173`) accurately identify interfaces/fakes only, unchanged admission, unresolved H1/H2, and real evaluation remaining NOT_RUN. §11's “public IPv4” statement needs the validator fix, and “capped deadline” does not itself prove trusted-clock provenance or hard-wait enforcement. The older design's demand to resolve H1 during S11a is read subject to the explicit offline limitation in §11 and this review request; it is not grounds to reopen H1 here. No new documentation claims native acceptance, and the added text contains no personal network, timezone, or proxy values. The acceptance matrix's native states remain unchanged. Historical statements elsewhere about S12 are outside this diff and are not re-audited here.

- **Simplicity:** Keep the closed operation inventory and fixed-size data; do not add transport selection, a controller, observer threads, or a real factory to satisfy this review. Delete the raw Debug prefix (finding 5). Two optional reductions are the duplicate `Row`/`Reservation` schema plus `Row::view` (`ledger.rs:150`), which can use one stored representation, and the speculative cross-field digest-distinctness rule (`manifest.rs:54`). Unequal program/image/policy hashes establish no trust or installation fact; matching actual pinned measurements belongs to the later trusted adapter. If retained, the manifest must continue to be described as data only, as it is today. Neither reduction requires a new abstraction.

Real Tart clone/start, VM/config identity, Softnet/host-guard enforcement, guest transport, egress probes, native permissions/Stop, login, and real model evaluation: **NOT_RUN by design**.
