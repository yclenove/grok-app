Must-fix, category (a), before merge:

1. **[P1; SAME CLASS as round-1 A1] Public `scope::Supervisor::start` still spawns an arbitrary backend before provider admission or ACK.** `gcu-eval/src/lib.rs:41`; `src/scope/mod.rs:37`, `:45`, `:70`, `:73`, `:79`.

   Schedule on Unix: an ordinary library caller provisions a real temporary environment through `LocalTempProvider::provision`, then calls the publicly exported `scope::Supervisor::start` with a regular executable wrapper as `binary`, that environment, a nonempty run id and the same minimal fake scope used by `tests/scope_supervisor.rs:61`. The wrapper uses shell built-ins to write an absolute start sentinel and exits 0; it ignores the appended `scoped-engine --driver fake ...` arguments. `prepare` creates the inherited control socket, and `command.spawn()` executes the wrapper before `bootstrap` attempts its first ACK exchange. `admit_launch`, `refuse_unsupported_launch` and `supervise` are never called. The wrapper needs no filename, adjacency, legacy declaration, race or successful protocol response. It can equally set a prearranged `GROK_HOME` and exec an absolute credentialed client/preflight binary before exiting. The eventual fixed bootstrap error cannot undo that execution and supplies no environment-contract report or run-level halt evidence.

   This method is unconditional production public API, not a `cfg(test)` launcher; its module's “fake-only” comment and supplied fake argv do not authenticate the executable. The normal `RunConfig::fake_scope` path is correctly refused before it reaches this method. Rounds 2–3 described standalone S3 bootstrap as separate machinery; under this round's explicit requirement that no unadmitted path construct a `Command` on any entry, that public path remains an A1-class gap. It predates these fixes and is not a NEW class or a regression in S3's ACK/lease state machine.

   Fix direction: close the path-taking production entry under the same admission policy. Preserve arbitrary-executable S3 bootstrap experiments in explicitly test-only support, or require a provider-admitted launch capability whose executable is bound through spawn. Do not grant another exemption based on fake argv, caller trust declarations or placement. Add a bounded regression through this actual public entry with a directly demonstrated harmless start sentinel; rejection must precede spawn/control bootstrap and expose the fixed unavailable-provider result. Keep the existing genuine fake-bootstrap lifecycle controls in the appropriate test surface. The new S3 admission harness tests `run_tasks` / `run_ab`, so its zero-start assertions do not cover direct `Supervisor::start`.

2. **[P2; NEW CLASS introduced by Round 3] In-process fake I/O can block the runner past its timeout and prevent cleanup.** `gcu-eval/src/exec.rs:81`; `src/fake_agent.rs:82`, `:122`, `:297`, `:320`; `src/access.rs:322`; `src/runner.rs:475`.

   Schedule on Unix: load the valid bundled `native-form-01` task; create a FIFO at an absolute synthetic probe path with no reader; set `builtin_fake=true`, leave both executable paths absent, set `probe` to that FIFO and `timeout=50ms`; run through the ordinary `block_on(run_tasks(...))` entry. Oracle self-test and fake admission succeed, and a private task root is allocated. `Invocation::run` reaches `write_probe` before its behavior branch. `std::fs::write` blocks opening the FIFO for writing. That synchronous call runs inside the first poll of the timed future on the current-thread runtime: neither the inner 50ms timeout nor an outer Tokio timeout can interrupt it. There is no longer a child process for `proc::run_command` to kill. The suite never returns a timeout/report or reaches `finish`/root cleanup. Forcibly killing the blocked owner bypasses its cleanup Drop and leaves the allocated task tree. No path substitution or malformed task oracle is needed.

   Before Round 3, this same probe write ran in the fake-agent child and the parent's process timeout could kill it and clean the task root. The replacement timeout regression (`tests/lockdown.rs:263`) selects the cooperative `tokio::time::sleep` branch, so it does not exercise the newly in-process blocking operations. The relocation harness's outer async timeout has the same inability to preempt them. This is an offline watchdog/cleanup regression; it does not establish an ordinary real-client escape.

   Fix direction: make invocation file I/O safe for the in-process execution model, including rejecting special-file probe destinations using a nonblocking/no-follow open and same-handle type validation. Preserve bounded timeout/cancellation and ownership of any work moved off the executor; merely wrapping blocking I/O in an async timeout, or detaching an uncancellable blocking worker that can write after cleanup, is insufficient. Add a production-runner FIFO regression with a separate process watchdog so a broken implementation cannot hang the test executor, plus a regular-file positive control. Require a bounded return, no post-return writes/work, and successful root cleanup; any actual cleanup failure must retain `not_run` and halt propagation.
