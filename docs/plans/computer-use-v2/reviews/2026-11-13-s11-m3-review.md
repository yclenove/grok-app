# S11-M3 independent code review — 2026-11-13

**Verdict: request changes. 6 P1 findings, 7 P2 findings; no P0 found.**

Reviewed branch `cu2/s11-m3`, commit `11f1aef1`, against parent `477ead0e`. Code paths below are relative to `computer-use/`. The review covers the entire new mailbox module, its tests, the `tart/mod.rs` exports, and the source-scan change in `tests/tart_offline.rs`.

Authority: ADR 0019 §3, §6 S11-M3, and the measured virtiofs constraints (a)–(e) at ADR lines 341, which take precedence over conflicting original text; implementer brief `/tmp/cu2-orch/grok-m3.md`. The brief is useful context, but pre-creating read slots does not authorize pre-creating exclusive publication sources or exporting staging.

This was a read-only source review. No builds, tests, real channels, VMs, mounts, or race reproductions were run, and no implementation files were changed. The controller's reported Linux/macOS fmt, clippy, and test passes are accepted as supplied evidence, not represented as independently rerun. The counterexamples below follow the reviewed control flow; proposed regression tests have not been added or executed.

## Findings

### R1 — P1: staging is inside the only directory that could be exported

**Evidence:** `crates/gcu-eval/src/disposable/tart/mailbox/slots.rs:385`, `:386`, `:387` create `host-write`, `guest-write`, and `host-stage` as siblings under the same supplied root. `:435`, `:436`, and `:795`/`:802` reopen those siblings directly. There is no intermediate `mailbox` export directory or separate staging-parent argument.

The resulting tree cannot satisfy the prescribed export layout. Exporting the common parent exposes `host-stage` alongside both message directories; exporting either message directory omits the other. ADR §3 lines 104–106 and 112/121 require staging outside the export and unreachable by the guest. The explicit volume layout at ADR lines 37–44 resolves the intended arrangement: `M/mailbox/{host-write,guest-write}` and sibling `M/host-stage`, with only `M/mailbox` exported. Mode 0700 and a recorded inode do not make an exported staging directory an independent protected parent.

This matters to the source-name check: a guest able to reach staging can replace the source after validation and before `renameat`. No real export is connected in this commit, so this is a defect in the prepared layout, not a claim that the current branch exposes a live host directory.

**Minimal fix:** accept the verified volume-root FD, exclusively create and record `mailbox`, put both message directories below it, and keep `host-stage` as its sibling. Traverse and validate both levels through FDs. Alternatively accept separately verified export and staging parents with the required same-filesystem and non-export relationship established by the caller.

**Missing test:** assert the actual parent/child layout and that the sole export subtree contains no staging directory; existing tests only address three siblings below a scratch root.

### R2 — P1: preparation occupies every exclusive guest publication source

**Evidence:** `slots.rs:395` creates every name returned by `guest_names`; `slots.rs:887`/`:888` chains the seven message names with all seven `.msg.tmp` names at `:892`. Consequently, for example, `guest-write/inventory.msg.tmp` already exists immediately after preparation.

ADR §3 line 123 requires guest tmp→msg publication and failure on an existing tmp. A conforming guest's first exclusive creation of `inventory.msg.tmp` therefore fails with `EEXIST`, before it can send the startup inventory reply. Reusing/truncating the placeholder would introduce the forbidden in-place-write fallback. Measured constraint (a) concerns names the guest will read; it does not require an exclusive staging source to exist before publication.

**Minimal fix:** pre-create guest `.msg` read slots only. Keep guest `.msg.tmp` names in the allowed-name set, but leave them absent until a publisher creates them exclusively.

**Missing test:** immediately after preparation, check that message placeholders exist and publication temp names do not, then perform one fake guest `O_EXCL` tmp→msg publication. All existing publication tests exercise the host source directory, so they miss the first-reply failure.

### R3 — P1: destination validation precedes the entire write/fsync window

**Evidence:** `slots.rs:445`/`:446` inspect and authorize the destination before tmp creation, writing, and fsync at `:447`–`:450`. After the `AfterFsync` hook at `:451`, only the source is checked (`:452`; `source_intact` at `:676`). The next destination operation is unconditional `renameat` at `:455`. The subsequent check at `:459` sees the newly published source, so it cannot detect the overwritten unauthorized target.

Counterexample: at `AfterFsync`, remove the destination, or replace it with a new regular inode, symlink, FIFO, or hardlink. The source remains intact. `renameat` can replace the changed entry and the method can return `Ok(())`. An absent target is also recreated despite the stated stricter rule that only a placeholder or the last published inode may be replaced. The existing source-replacement test does not exercise this destination window.

This omits publish step 5 **after** source fsync/revalidation. It does not follow a destination symlink, but it does publish onto a target that the current authorization check would reject.

**Minimal fix:** after source validation, revalidate the destination parent and call `stat_name`/`accept_target` again immediately before `renameat`. Keep the post-rename verification and both directory fsyncs. This closes the whole write/fsync window; it does not claim atomic compare-and-rename or eliminate the final race already acknowledged by the ADR.

**Missing test:** use the existing `AfterFsync` hook for each destination substitution, including absence. Assert error and no rename, preserving the replacement and the staged source for failure evidence.

### R4 — P1: directory revalidation never checks that its name still names the recorded directory

**Evidence:** `open_recorded` at `slots.rs:578` opens a directory and checks its FD. `dir_ok` at `:595` only calls `fstat` on that FD. Read completion (`stable`, `:749`) and publication completion (`published_intact`, `:708`/`:709`) repeat that same check. No final `fstatat(root, directory_name, AT_SYMLINK_NOFOLLOW)` verifies the directory's parent/name relationship. The file-name check at `:751` is relative to the already-open old directory.

Counterexample: in `AfterRead`, rename `guest-write` aside and replace its original name with a different directory or symlink. The old directory FD still has exactly its recorded kind/dev/inode, and the file remains present inside it. `stable` succeeds and `poll_guest` can return a ready reply from the detached directory. The analogous `AfterFsync` replacement of `host-write` lets publication complete in the renamed directory and report success while the named mailbox contains something else.

Using kind/dev/inode rather than directory timestamps is correct; checking those fields only through the retained directory FD does not detect a replaced directory entry. This falls short of the directory/path revalidation in read step 1 and publish steps 5/7.

**Minimal fix:** retain the trusted parent/name information within each call and compare no-follow `fstatat` of every directory entry to the recorded identity and the opened FD, before accepting read bytes and before/after publication. Include the new `mailbox` level when fixing R1. Missing/replaced directories must fail the directory contract, not authorize success through an old FD.

**Missing test:** swap whole parent directories at `AfterRead` and `AfterFsync`, preserving the old directory elsewhere so its FD remains usable. Current directory tests replace a message with a directory, not a directory in the traversal chain.

### R5 — P1: valid active/pending inventory snapshots cannot be decoded

**Evidence:** `crates/gcu-eval/src/disposable/tart/mailbox/wire.rs:185` matches `(active_op, active_result)` and permits only `(None, None)` or `(Some(op), Some(body))`. `(Some(op), None)` always returns `CodecFault::Shape` at `:188`. In contrast, `ops.rs:265`/`:266` correctly define pending activity as a present op/nonzero sequence with no result, and `wire.rs:211` can encode it.

A valid snapshot containing `active_op="login", active_request_seq=1, active_status="pending", active_result=null` is rejected. Thus `decode_frame(encode_frame(valid_pending_snapshot))` fails, and `poll_guest` turns an ordinary running operation into a sticky malformed-slot error (`slots.rs:354`/`:355`). ADR §3 line 161 explicitly requires this pending shape.

**Minimal fix:** permit `(Some(_), None)` to produce no result and let `Activity::new` enforce whether the accompanying status and sequence make it legal. Retain rejection of `(None, Some(_))` and terminal-without-result.

**Missing test:** round-trip pending activity for bootstrap/login/run through both envelope and normalized-reply codecs, then poll it through the joined slot/tracker API. `tests/codec.rs:115` tests a terminal snapshot; the shared inventory fixture at `tests/support.rs:79` always uses `none`.

### R6 — P1: side effects can complete through their own wire slots, bypassing the prescribed inventory completion route

**Evidence:** `ops.rs:488`–`:495` admit outer terminal envelopes for bootstrap/login/run/revoke. `wire.rs:107`–`:109` and `:125` decode them. `seq.rs:247`–`:250` accepts an outer terminal from either Open or Accepted, and `:358`–`:371` returns it as a normalized terminal result. `tests/seq.rs:87` explicitly codifies accepted→terminal in the bootstrap slot as successful completion.

The authoritative table at ADR lines 155–159 places these completions in `inventory.active_result` or `inventory.revoke_result`, after accepted, with retention and consumption at lines 166–170. It does not authorize changing an accepted message into a terminal on the same side-effect slot/seq. Here even a terminal without an accepted can succeed. A future adapter using the normalized result could finish bootstrap/login/run/revoke without the inventory snapshot/retention path the protocol requires. This stated deviation conflicts with the closed operation table; the virtiofs amendments do not authorize it.

**Minimal fix:** reject outer terminal wire envelopes on these four slots. Preserve their terminal result types for inventory rows and for a local normalized completion derived from a validated inventory snapshot. Keep same-seq changed-byte rejection on the accepted slot; add inventory-based completion/consumption routing in the assigned M4 state machine.

**Missing test:** reject direct side-slot terminal envelopes, with and without an earlier accepted. Replace the current success fixture with the ADR's accepted→inventory terminal→machine consumption→consume-confirmation sequence at the appropriate layer.

### R7 — P2: stale lease ACKs bypass the previously seen byte identity rule

**Evidence:** `seq.rs:279`/`:280` returns `DiscardedLease` before looking at `replay` or recording seen bytes. Only the current lease reaches `:282`–`:294`. `same_grant` at `:336` compares the three numeric fields, not the previously observed frame bytes. No fingerprint is saved for an ACK first seen when already stale.

After observing lease 1, send lease 2, then return lease 1 with reordered keys, a changed legal escape spelling, or added interior whitespace. Binding and the grant fields still match, so the changed bytes are accepted as discarded. The same re-encoding while lease 1 is current is rejected as Changed. First-seen stale ACKs can likewise change representation indefinitely without a saved fingerprint. ADR lines 172–174 require same-byte replay handling and retention of seen reply fingerprints for the lease exception. Numeric-field mismatches are correctly rejected and neither path extends the deadline; the defect is the missing identity check/history on the stale path.

**Minimal fix:** keep a seen fingerprint/bytes per issued lease, including first-seen stale ACKs. Compare it before the stale-discard return and fail on a changed frame. Save it on first valid observation, then discard stale ACKs without moving the deadline.

**Missing test:** observe an ACK while current, advance the lease, then re-encode the same grant with different bytes; also vary a first-seen stale ACK on its second observation. Existing stale-lease tests at `tests/seq.rs:223` reuse exactly the same byte vector.

### R8 — P2: source-scan exceptions match unintended production files and checkout ancestors

**Evidence:** `crates/gcu-eval/tests/tart_offline.rs:914` uses the suffix `mailbox/sys.rs`, so `src/disposable/tart/machine/mailbox/sys.rs` also receives the unsafe exception. Lines `:915`/`:916` test whether **any components of the absolute path** are `mailbox` and `tests`; `machine/tests/mailbox/live.rs` receives the filesystem/environment exception. Checking out the repository below a directory named `tests` gives that exception to ordinary production files such as `mailbox/ops.rs`. Lines `:918`–`:922` then skip the relevant forbidden tokens without checking compilation gating.

These are direct consequences of the path predicates, independently checked using representative path components during review. The current module does put unsafe only in the intended sys file and filesystem/environment access in cfg(test) code. The regression guard, however, does not enforce that boundary and can be bypassed by ordinary Rust module paths, without token aliases.

**Minimal fix:** first strip the exact scanned source root. Match unsafe only for relative path `mailbox/sys.rs`. Limit filesystem/environment exemptions to the exact known mailbox test sources below `mailbox/tests/`, and verify their module entry stays `#[cfg(test)]`; do not allow production `#[path]` imports to re-use those exempt sources. Retain all process/wait restrictions.

**Missing test:** exercise the exemption classifier with the valid paths, nested `machine/mailbox/sys.rs`, unrelated `tests/mailbox` paths, a repository ancestor named `tests`, and production imports of an exempt source.

### R9 — P2: nullable wire fields are optional rather than required-nullable

**Evidence:** `wire.rs:367` declares `RawEnv.boot_id` as `Option<String>`; `:433`, `:440`, `:447`, and `:469`–`:471` use `Option` for terminal values; `:481`, `:484`, and `:487` do likewise for snapshot fields. Serde's derived struct deserializer supplies `None` when these fields are omitted, as well as when they are explicitly null. The subsequent shape checks cannot distinguish the two.

For example, removing `boot_id` entirely from the first inventory request is accepted. A failed bootstrap terminal can omit `native_ack_generation` entirely, and a failed revoke can omit all three flags. The schema requires the common fields and explicit null value fields for non-ok outcomes (ADR lines 144–149), rather than a second wire shape with missing fields. Unknown fields and duplicate keys being rejected does not close this omission case.

**Minimal fix:** deserialize required nullable fields through a helper/custom deserializer that accepts JSON null but has no missing-field default, or enforce exact key presence before typed conversion. Apply it consistently to envelopes, inventory requests/snapshots, and outcome values.

**Missing test:** independently remove each nullable key from otherwise valid frames and require rejection; retain positive tests for explicit null. Include nested non-ok active/revoke results.

### R10 — P2: an old exact frame reports the old request as the current pending request

**Evidence:** `seq.rs:235`/`:236` calls `pending(env)` on any known exact replay. `pending` at `:342`–`:346` copies `env.request_seq`, not the currently sent request. `slots.rs:338`–`:342` forwards that value unchanged, despite `GuestPoll::Pending` documenting it as the request still outstanding at `:128`. `tests/seq.rs:154`–`:157` explicitly expects sequence 1 after request 2 has been sent.

ADR line 172 says the old identical bytes mean to keep waiting for the **current** request. With request 2 outstanding and sequence 1 still visible through virtiofs, the joined API instead reports pending request 1. An adapter that uses the normalized request identifier to correlate progress receives the wrong identifier on this ordinary transient path.

**Minimal fix:** build replay Pending with `self.outstanding(env.op)` while retaining the old sequence only as optional diagnostic data. Keep the actual pending operation/request stable while discarding an old frame.

**Missing test:** after request 2 is recorded, poll a still-visible exact reply for request 1 and assert pending/request_seq=2, including the joined filesystem API.

### R11 — P2: a stable byte-count mismatch is classified as replacement instead of sticky torn data

**Evidence:** `slots.rs:517` first establishes that the FD metadata and named object are stable. If the subsequent byte-count comparison fails, `:520`/`:521` still calls `replaced(watch)`, which increments a transient retry and returns Pending without setting `stuck`.

Once stability has passed, a short read versus the recorded size is not supported by any detected replacement. A cap+1 read inconsistent with a supposedly in-cap stable size has the same problem. This branch hides contradictory/torn bytes as a visibility retry rather than following the explicit malformed/torn/oversize sticky rule. On an ordinary coherent local filesystem this is difficult to produce with unchanged metadata; the important untested case is a filesystem view returning inconsistent data and metadata. The review does not claim to have reproduced it on virtiofs.

**Minimal fix:** after successful stability validation, treat a byte-count mismatch as a sticky torn-frame/size breach. Reserve `retry_replaced` for actual metadata/name identity changes. Add a dedicated fault if needed to preserve the distinction in evidence.

**Missing test:** a fake syscall/filesystem seam that returns stable pre/post metadata but EOF before the advertised size, and a cap+1 byte return with in-cap stable metadata; subsequent reads must remain failed.

### R12 — P2: sticky state and retry totals are replaceable caller data, not state bound to a slot

**Evidence:** `slots.rs:61` derives Clone and Default for `SlotWatch`, and `:64`/`:66` expose writable retry totals. `read_slot` takes a freely supplied watch independently of its `Layout` and `SlotRef` at `:264`–`:269`. The only sticky gate is that supplied watch's private bool at `:277`. The layout stores neither watches nor an association to a particular slot.

With the **same watch**, a sticky error is correctly preserved across `read_slot`, `read_checked`, and `poll_guest`, and no internal success path resets it. But after a malformed/oversize/binding failure, supplying a fresh default watch (or a clone taken before failure) for that same prepared slot permits a later success. Assigning either public counter to zero silently changes subsequent evidence. Accidentally sharing a watch across different slots also misattributes failures/counters. The stronger requested guarantee—same-slot failure persistence and retry totals that cannot silently reset—is therefore not enforced by these APIs.

**Minimal fix:** own the watch records in one attempt/slot state owner keyed by `SlotRef`, initialize them only when preparing a new attempt, and expose read-only counter access. Do not expose interchangeable pre-failure state clones as active slot state. Keep counters in both successful and failed read results.

**Missing test:** use every public read entry point after a failure of the same slot; verify that changing entry point cannot obtain a fresh watch or clear evidence, and that operations on a different slot do not alter this slot's state.

### R13 — P2: the bounded directory whitelist preflight is absent

**Evidence:** `slots.rs:481`–`:493` proceeds from opening the selected parent directly to `fstatat`/open of one fixed message. Neither `slots.rs` nor `sys.rs` implements directory enumeration. Therefore there is no check of the export's two-child layout, host-write's eight-name limit, guest-write's fourteen-name limit, or the byte whitelist for other entries. The race fixture itself creates an unrecognized `host-write/spare.dat` at `tests/slots.rs:258` and still reads successfully.

ADR read step 2 at line 128 explicitly requires reading at most whitelist-size+1 entries per layer and no-follow preflight, without recursion, sorting, or scanning to stability. Fixed name constants prevent arbitrary caller paths and keep the message read bounded, but they do not detect an already breached directory layout. The measured amendments change absent/replaced-slot handling, not this preflight requirement.

**Minimal fix:** add an FD-based bounded enumeration/preflight in the syscall boundary, check exact raw entry-name bytes and permitted object kinds, and stop at the per-directory allowance+1. Allow only the prescribed temp names where appropriate; do not require temp files to exist. Preserve ENOENT/replacement handling for the selected message.

**Missing test:** one unknown ASCII name, a non-UTF-8 name, an unexpected link/special entry, and allowance+1 entries at each checked layer. Update replacement fixtures to use an allowed publication source rather than relying on an invalid extra entry.

## Unsafe/FFI audit

All **17 unsafe blocks** in `sys.rs` were inspected. No P0/P1 memory-safety or ABI defect was found in those blocks for the requested macOS and Linux targets. This does not clear the higher-level filesystem contract defects above.

Additional checks:

- **Errno:** `retry_int`/`retry_isize` at `sys.rs:256`/`:269` inspect errno only after a negative return and retry EINTR; callers do not treat a failed operation as success. `map_last` at `:282` maps the specified special cases. The two immediate `last_os_error` reads do not have an intervening syscall in this implementation. No close retry or manual close can double-close an adopted FD.
- **FD lifetime:** only successful `open`/`openat` create owners. Other helpers borrow integer FDs; local `OwnedFd`s drop on every return path. The source remains owned through publication verification. `Layout`, `SlotWatch`, and `SeqTracker` store no descriptors; no cross-poll retained FD was found.
- **Names/NUL:** production callers use `c"..."` literals selected through closed enums/constant arrays. No arbitrary path string or CString construction reaches a production open/rename helper. Full-path CString construction occurs only in the tests and checks for NUL.
- **Metadata conversion:** `sys.rs:226` reads native fields. macOS signed `dev_t` is bit-preserved via u32 before widening (`:309`); inode/link/time conversions cover the reviewed native widths; negative sizes fail instead of becoming huge unsigned lengths (`:360`).
- **Flags:** directory opens use O_DIRECTORY/O_NOFOLLOW/O_CLOEXEC (`:107`); reads use O_RDONLY/O_NOFOLLOW/O_NONBLOCK/O_CLOEXEC (`:117`); exclusive creation uses O_CREAT/O_EXCL/O_WRONLY/O_NOFOLLOW/O_CLOEXEC (`:127`). O_EXCL prevents an existing FIFO/device from becoming an opened creation target, so O_NONBLOCK is not needed on that creation call.
- **Blocking limit:** O_NONBLOCK addresses FIFO reads, not disk/fsync or arbitrarily repeated EINTR. The ADR explicitly assigns provider deadline/kill/reap to the outer owner; this offline layer does not establish syscall wall-clock bounds. No new waiting thread or process path was found.

## Protocol coverage and boundaries

**Codec strictness that is present:** `codec.rs:53` checks total frame size, four-byte BE prefix, and equality with remaining length; `:20` requires UTF-8 before parsing. The pre-scan enforces container depth ≤3 (`:104`, `:133`), array length ≤16 (`:144`), checked u64 accumulation and rejection of negative/fraction/exponent/leading-zero forms (`:95`, `:159`). It rejects trailing bytes, including trailing whitespace (`:74`). Typed decoding then constrains UID to u32 and op/status/enums to their closed variants. All wire objects use `deny_unknown_fields`; nullable-field presence remains R9.

Keys are decoded before duplicate comparison (`codec.rs:115`–`:119`); `"v"` and `"\u0076"` therefore collide, as tested. Escape handling at `:210`/`:226` accepts only printable ASCII after decoding, so `"\u0000"`, raw control characters, non-ASCII, and surrogate encodings fail before serde. No escape-based duplicate-key or NUL disagreement that reaches serde was found. ASCII identities are capped at 64 bytes and further restricted by `ids.rs:16`. Digests are exactly 64 lowercase hex characters decoded into the existing 32-byte `manifest::Digest`, including its all-zero rejection (`ids.rs:72`–`:81`; `manifest.rs:22`). Manifest itself has no competing textual wire encoding.

**Read/publication behavior that is present:** file-type/link-count/device/FSID checks use the opened file FD (`slots.rs:722`); the read is capped at 4097 bytes; pre/post metadata compares dev/inode/nlink/size/mtime/ctime/kind (`:813`), and no-follow final lookup verifies the selected file name still names that opened dev/inode (`:751`). A message replaced after reading is discarded and counted; pre/open ENOENT is pending with a counter (`:484`, `:493`, `:760`). Source-name replacement after fsync is detected through FD/name comparison (`:676`) before rename. The tmp is retained on failure. These checks do not repair R1–R4, R11, or the missing directory preflight.

The tested initial symlink/FIFO/directory/nlink=2/oversize cases fail without following the symlink or blocking on the FIFO. Oversize and codec/sequence failures stick with the same watch; retry counters use checked addition and appear in both successful results and `FailedRead`. Stable malformed frames are decoded only after structural checks. No product path was found that follows a caller-selected link or reads an unbounded number of message bytes. Device-node safety still relies on the ADR's independently established nodev mount prerequisite.

**Sequence/binding behavior that is present:** `seq.rs:149` validates request status, echo, attempt binding, next sequence, boot, and the inventory/lease caps before changing state. Sequence starts at 1 and checked successor rejects wrap (`:313`). First inventory request requires null boot, its terminal pins boot, and all subsequent request/reply boot values must match (`:172`, `:207`). Replies reject wrong op/status/binding/echo and zero/future sequence (`:184`); ordinary old frames must have been seen byte-for-byte or fail (`:235`). Initial and lease-overflow errors leave the request state unchanged. Inventory/lease issuance is capped at 2048 each. `sample_ms + 2000` is checked host-side (`:324`) and every lease ACK must match an actually stored grant (`:273`–`:277`). ACK observation does not update the deadline. R6/R7/R10 are the exceptions found in this logic.

**Consumption/M4 boundary:** this commit validates the shape of inventory consume fields (`ops.rs:351`) and active/revoke rows, not the complete consumption state machine. `SeqTracker::admit_request` does not check whether a consume pair names a terminal already delivered and recorded by the machine. `observe` checks the envelope's sequence, but does not correlate nested `active_request_seq`/`revoke_request_seq` with issued side effects, detect a retained result changing/disappearing across different inventory samples, or enforce one ordinary effect in flight. These are not proven by the passing M3 tests. Under §6's assignment of all seven-method transitions to M4, they must be implemented and tested there before any snapshot becomes a side-effect completion or consume confirmation. Do not interpret an M3 `Observe::Reply(Inventory(...))` alone as successful validation of those nested operation claims. This review does not request wiring `machine/` into M3 to close that future obligation.

**Binding/M4 boundary:** `binding.msg` is explicitly opaque here (`slots.rs:300`), with only structural size checks and publish-once protection (`:431`, `:468`). The round-trip fixture deliberately uses unframed `b"binding-v1"` (`tests/slots.rs:77`). Thus this module does not prove the binding's required framing, closed constants/digests, or absence of secrets/scope tokens. A typed binding encoder/validator must supply those guarantees before M4 publishes it; publish-once alone does not validate its contents. This is an explicit interface limitation, not evidence that arbitrary binding contents are authorized by §3.

Zero-length placeholders as pending, missing publish targets as breaches, transient absent/replaced counters, raw FSID comparison on these platforms, directory identity based on kind/dev/inode, retained failed temps, and host-computed lease deadlines are reasonable amendments/choices within the stated boundaries. Direct side-slot terminal completion is the incompatible deviation described in R6. The cumulative 128 KiB poll budget and real lease age/gap/expiry enforcement remain M4 obligations; individual M3 reads remain capped, and no claim that a sequence of them satisfies the cumulative budget is made here.

## Scope and verification assessment
