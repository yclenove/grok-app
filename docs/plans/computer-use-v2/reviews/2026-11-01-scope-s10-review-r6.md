Round-5 latch / doctor hunt:

- **SAME CLASS — late marking, clearing, and binding order do not reproduce S2 A5 here.** The constructor marks its owned `D` synchronously before storing it in the private `Arc` (`gcu-core/src/scope/driver.rs:59`, `:64`). Linux is not Clone; the wrapper exposes neither its inner driver nor mutable access. Both binding setters require `&mut LinuxDriver` (`driver.rs:339`, `:350`), so safe callers cannot bind or replace that driver after wrapping. All Linux constructors converge on `new_internal`, which initializes the flag once (`:160`); the only subsequent store is `true` (`:1128`). Pin cleanup, release, rebind, Stop and Drop have no clearing store. Thus the S2 schedule “first read sees scoped, another action clears pin, second read falls back to unscoped” has no corresponding mutable Linux decision slot. Calling the public marking hook manually before binding is possible while the caller still owns the driver; subsequent binding leaves the flag set and its already closed capability snapshot conservative. It does not clear enforcement or reopen the ordinary enumerators. Binding before wrapping still takes the existing bound paths, including asynchronous doctor probes.

- **SAME CLASS — the missing-binding refusal covers the shortcuts too.** `perform_action` independently refuses before inspecting the attached portal (`perform.rs:33`), and `admit_wayland_window` also refuses missing binding (`driver.rs:472`). `route_is_wayland` uses memory for either a binding or a marked session (`:418`); `action_xid` refuses before its ordinary resolver (`perform.rs:302`). A failed proof cannot select the old X resolver, AT-SPI semantic fallback or desktop capture. Private tree and ordinary-geometry helpers also have the unbound check (`driver.rs:493`, `:527`). No Linux clipboard read/write sink was introduced; paste chords inherit the closed scoped key route. Cleanup remains the permitted exception to target admission.

- **SAME CLASS — doctor without probes is specifically the unbound scoped case.** Its early return is before the portal shortcut and both extension queries (`driver_wayland.rs:291`). `extension_flags` independently refuses missing binding (`:389`). It returns no app/window facts or raw probe errors.
