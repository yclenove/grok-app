Must-fix, category (a), before merge:

1. **[P1; A1 residual; SAME CLASS as round 1] A copied genuine helper can bless an arbitrary executable placed beside it.** `gcu-eval/src/fake_agent.rs:159`, `:160`, `:166`, `:173`; `src/boundary.rs:82`, `:93`, `:102`, `:105`.

   Schedule on Unix: copy the genuine `eval-fake-agent` into a fresh directory D, and create a regular executable wrapper at `D/eval-fake-gcu` that writes a harmless start sentinel and exits 0. Invoke the copied agent with `GCU_EVAL_BEHAVIOR=crash` and `GCU_BIN=D/eval-fake-gcu`, with all three trust/re-entry markers absent. No fixture or credential files are needed. `current_exe()` makes D the supposed artifact directory; the wrapper's regular-file, basename and directory checks all pass. `Command::status` starts it with the caller's inherited environment, and the agent subsequently returns its scripted 101. The same schedule works with a copied genuine `gcu-eval` using its hidden fake-agent entry. The standalone agent also accepts a forged sibling named `gcu-eval` when the re-entry selector is 1. A Windows sentinel executable with the corresponding `.exe` name satisfies the same checks.

   The started wrapper can ignore `--driver fake` and start a credentialed client or its tool preflight. Neither provider admission nor an environment receipt exists on this path. This requires no race, hard link, modification of a genuine binary, or write to the original build directory; the documented hard-link replacement limitation does not describe it. The README's “verified … in the same build directory” claim (`eval/README.md:89`) exceeds what the code establishes.

   Fix direction: make the fake helper's backend execution depend on code identity established independently of caller-chosen placement. Prefer executing the built-in fake implementation directly, or a genuine self-reexecution where available; if sibling artifacts remain supported, authenticate their build/content identity and preserve it through launch. A basename, adjacent directory, or new environment marker cannot be the authority. Add bounded start-sentinel regressions that relocate the genuine caller into D and supply forged siblings for both entries and both backend forms, plus genuine-artifact positive controls. Keep every external backend subject to the unavailable provider policy.

2. **[P2; A4; NEW CLASS introduced by the A1 fix] The runner admits an offline S3 backend that the fake agent refuses, then scores the refusal as a crash and continues.** `gcu-eval/src/disposable.rs:582`, `:591`; `src/runner.rs:459`, `:474`; `src/launch.rs:179`; `src/fake_agent.rs:159`; `src/exec.rs:98`, `:161`, `:215`; `src/runner/provider.rs:114`.

   Schedule on a supported Unix build: call `run_tasks` with a valid ordinary task, `run_local=true`, `real_driver=false`, `builtin_fake=true`, the genuine sibling `eval-fake-agent`, `gcu_bin` pointing to the genuine sibling `gcu`, and a valid in-memory `fake_scope` (the empty S3 scope is sufficient). Set the retained attestation flag to true to pass the unchanged `external_backend_block` at `src/boundary.rs:142`; this flag supplies no provider evidence. Use behavior `crash` to reach backend admission without depending on fixture contents, and provide a second task.

   `trusted_fake_scope` explicitly admits this compiled `gcu` backend. `start_scope` starts the actual fake scoped engine, obtains its ACK, and returns its data address (`src/prep.rs:423`). The task client then starts. Its `GCU_BIN` remains the same `gcu`, with no re-entry selector, so the new check requires the different basename `eval-fake-gcu` and returns `provider_unavailable` before invoking it. The agent exits 1; `execute_ready` records `client_started=true` and `RunStatus::Crash`, with no environment refusal or cleanup-failure bit. Successful S3 close/root deletion leaves `InheritedStop::from_outcome` returning None, so the next task, and subsequent A/B attempts, start. A late backend-policy refusal has become a scored crash instead of `not_run` and stop. With scripted behavior, the same rejection occurs at the first backend call after synthetic state writing. This does not establish a real-client escape; it is a new inconsistency in the supported offline launch/refusal path.

   Fix direction: share a single backend admission decision between the runner and helper. Either preserve this verified S3 fake-only composition with an appropriate offline execution path, or refuse the unsupported composition before starting its engine/client and propagate the fixed refusal as `not_run` plus run halt. Do not restore declaration-based backend authorization. Add a bounded regression through actual `run_tasks` with the real S3 engine and fake client; cover both the intended positive composition and unsupported combinations, later-task/arm/repeat suppression, and client-start/report provenance. The new positive executable control uses only `eval-fake-gcu` and `gcu-eval` (`tests/fake_agent_boundary.rs:34`); the new `fake_scope` test supplies an untrusted sentinel (`src/disposable/tests.rs:804`). Neither reaches this disagreement.
