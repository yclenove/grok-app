# S11-0 probe independent review — 2026-11-01

**Verdict: REWORK.** Do not run this revision on the owner's Mini. A clone-name collision can cause deletion of somebody else's VM; the advertised hard deadline does not bound several blocking calls; and several observations cannot answer the network questions attributed to them. Reduce the script before repairing it.

Reviewed `cu2/probe-s11-0`, commit `d56c7083`, against parent `7ccadb5a`. Read ADR 0018 §5 and §10 first, then all 1,998 script lines, all 894 test lines, the runbook, the verify hook, and the relevant workflows. Findings below are static failure scenarios, not reproductions on macOS. Paths are relative to `computer-use/`, except explicitly named repository-root paths.

Validation: `bash -n` passed for the probe, stub tests, and `verify.sh`. The unmodified Linux stub suite passed **24/24**, taking **33.53 seconds** with Bash 5.2.21; ShellCheck was unavailable. No network, real Tart/Softnet invocation, SSH connection, VM operation, or Mac execution was performed. No code or existing documentation was edited. Mutation examples below were assessed from the assertions, not executed.

1. **must-fix — A name is claimed before ownership exists.** `scripts/s11-0-probe.sh:1445`, `:928`, `:939`, `:689`, `:1859`.

   **Principle: destruction requires ownership, not a matching prefix.** Supply `--clone-name s11-0-probe-existing` when that VM already exists. `begin_clone` sets `OWNED_CLONE` before calling Tart. If Tart rejects the existing destination, the failure exit invokes cleanup, which stops and deletes that pre-existing VM. Stage B has the same problem with the appended `b` name. Without the override, the random suffix contains only 32 bits and does not eliminate collisions. The inventory precheck verifies the golden's state but never checks either destination.

   **Minimal fix:** remove the reusable clone-name option from the operational interface; reserve a fresh destination and check authoritative absence before cloning. Establish the new instance's identity before authorizing stop/delete. A failed or partial clone must not turn an ambiguous destination into owned property: clean it only when creation by this invocation is established; otherwise report the ambiguity and stop. Keep registration before the potentially partial operation, but distinguish reservation from verified ownership. Do not merely move the assignment after successful clone and lose partial-clone accounting.

2. **must-fix — The deadline is checked around calls that can block indefinitely.** `scripts/s11-0-probe.sh:1215`, `:1240`, `:1315`, `:1337`, `:1352`, `:1940`, `:1089`, `:850`.

   **Principle: a deadline must bound the operation itself.** `tart --version`, `tart list`, and every `tart ip` execute without a timeout wrapper. The IP-loop limit is checked only between calls. `ssh_up` has `ConnectTimeout=8`, but no session deadline or `ServerAliveInterval`/`ServerAliveCountMax`: a guest that authenticates and then stalls `/usr/bin/true` can hold it indefinitely. Bash can defer a TERM trap while waiting for a synchronous foreground command or command substitution. The watchdog sends TERM only to the shell, so it does not make these calls bounded or guarantee entry into cleanup.

   Cleanup also kills the watchdog first and uses `run_bounded_simple`, which ignores `DEADLINE`. Stop/delete budgets and kill grace can run past the claimed 2,400-second total, and report writing has no remaining-time bound. Timers use wall-clock `date +%s`, so backward clock changes can extend them.

   **Minimal fix:** use one portable, tested subprocess wrapper for every Tart/SSH call, including prechecks and IP discovery; give SSH both liveness options and an enclosing command limit. Reserve cleanup within a fixed total budget, bound cleanup/report work, and use elapsed time independent of clock adjustments. Bound captured output too: current captures and the Tart run log have no size limit. A loop condition and a shell-only watchdog are insufficient.

3. **must-fix — Cached PIDs do not prove process ownership or complete tree termination.** `scripts/s11-0-probe.sh:708`, `:768`, `:803`, `:836`, `:869`, `:892`, `:902`, `:1092`, `:334`.

   **Principle: signal only an owned process instance, and finish reaping it.** If `tart run` exits during probing, Bash can reap it asynchronously while `TART_RUN_PID` remains recorded. If the number is reused before cleanup, `kill_recorded` accepts `kill -0` and signals the replacement process, potentially its whole group. There is no parent/start-identity check. Separately, after TERM to a group, the function returns as soon as the leader disappears; a surviving descendant can avoid the KILL escalation. Timeout branches clear the child variable without `wait`, and `destroy_owned` likewise does not reap the run process. The guest capture helper signals only the leader even when it used `setsid`.

   Cleanup resets INT/TERM to their defaults before stop/delete. A second Ctrl-C or TERM can therefore interrupt cleanup and strand the clone. HUP is not handled explicitly either. These are additional limits to the runbook's blanket signal-cleanup statement.

   **Minimal fix:** consolidate the duplicated process runners into one owner that retains and reaps the direct child, verifies its instance before signaling, and completes termination of its owned process group within a cap. Do not signal an old numeric PID simply because it exists. Make bounded cleanup resistant to repeated cancellation signals, and record stop/deletion confirmation rather than relying only on command exit zero. Unavoidable hard-kill/power-loss recovery should be described separately.

4. **must-fix — `blocked` combines policy denial with ordinary absence and network failure.** `scripts/s11-0-probe.sh:178`, `:185`, `:207`, `:214`, `:256`, `:286`, `:297`; `docs/s11-0-probe-runbook.md:43`.

   **Principle: report the observed cause; lack of service or route is not proof of filtering.** A gateway with no listener returns connection refused even when the guest reaches it successfully; this becomes `blocked explicit-reject`. An unconfigured IPv6 guest returns “no route” and is also marked blocked. `ipv6_addr_class` explicitly calls link-local-only or no-address configurations blocked. ICMP unreachable can originate from normal routing or a destination port, not Softnet. These cases cannot establish §5's denial behavior. Conversely, `nc -z` without verbose diagnostics may supply no rejection text, so the same refusal can become `error timeout`; unknown-option/tool errors also fall into that timeout label. Classification depends on incidental English text rather than a reliable cause.

   **Minimal fix:** preserve transport observations such as connected, refused, no-route, no-address, timeout, and tool-error separately. Use `unknown`/`error` for policy conclusions without an external denial observation. Keep refusal as evidence that some network path responded, without claiming an application connection or attributing the refusal to Softnet. Correct the runbook legend and tests, which currently require the misleading IPv6 classifications. Do not reinterpret all nonzero statuses as denial.

5. **must-fix — The UDP payload cannot answer the QUIC question, and coverage is incomplete.** `scripts/s11-0-probe.sh:225`, `:243`, `:246`, `:444`, `:465`, `:468`, `:1456`.

   **Principle: a negative experiment needs a working stimulus and an observable response or receiver.** The purported QUIC case sends the five bytes `probe`. An entirely reachable QUIC server can silently discard this invalid packet, yielding exactly the same `error timeout-no-icmp` as a network drop. Keeping that case as error is honest, but it does not measure whether the datagram left the guest. The stub supplies a reply to every UDP/443 payload and hides this limitation.

   Coverage limits also matter: DNS has distinct gateway/public UDP probes, which is useful, but TCP/53 is tested only at the gateway, not the public resolver; there is no DoT/DoH check. IPv6 tests one global TCP destination and local address presence, not IPv6 gateway, link-local/ULA, or UDP paths. UDP/443 tests only the endpoint, not gateway/non-allow destinations. The automatically selected LAN address is the host's own default-interface address, so it does not establish access to another LAN machine. No counters or controlled receiving endpoint are observed. These samples cannot justify dropping the §5 guard.

   **Minimal fix:** use one valid, bounded, credential-free UDP/QUIC exchange or an approved receiver with a fresh nonce. If neither exists, record the question explicitly as unmeasured and remove the QUIC claim. Add an explicit measured/unmeasured coverage list rather than expanding into a scanner. Any absent category or absent external policy observation remains unknown under ADR §5. Keep LAN targets explicit and approved; do not scan the owner's network.

6. **must-fix — The report states intended policy rather than recording launched argv.** `scripts/s11-0-probe.sh:982`, `:1055`, `:1482`, `:1493`, `:1689`.

   **Principle: evidence must be derived from the operation performed.** The actual B launch does contain the required `--net-softnet`, `--net-softnet-block=0.0.0.0/0`, and `--net-softnet-allow=<IPv4>/32`, plus the appropriate `--no-graphics`. However, reports print constant policy labels and `endpoint/32`; they never serialize the arguments passed to the launcher. Those labels appear even for a precheck failure, and `stage_b_ran` becomes true before clone or launch succeeds. A later launch regression or argument/VM mismatch can therefore leave a plausible policy report. Dry-run output is a separately maintained implementation, not evidence of the real invocation.

   **Minimal fix:** construct a single argv array, pass it unchanged to launch, and record that exact array, the stage/clone binding, and launch outcome. An approved public endpoint address in those arguments is distinct from the owner's LAN data; preserve enough information to verify the actual `/32`. Record “launched” only after launch was attempted/succeeded as defined, and label absent launches explicitly. Generate the dry run from the same representation. This does not require implementing the future provider's entire policy-attestation machinery.

7. **should-fix — Failed guest execution is silently promoted to a complete run.** `scripts/s11-0-probe.sh:1426`, `:1522`, `:1990`.

   **Principle: experiment completion and an unsuccessful observation are different facts.** After SSH readiness, suppose the guest script cannot execute, exits nonzero, or the outer guest-command timeout expires. `run_guest_net` fills missing rows with errors and returns the failure status, but `run_net_stage` discards it with `|| true` and returns success. `--stage A` or B can finish with exit zero and `status=complete` despite collecting no guest measurements. An all-stage run can do the same if C later succeeds. This is not literally error-to-blocked conversion, but it contradicts exit code 4's “partial probes” meaning.

   **Minimal fix:** retain the guest transport/execution status in the report and propagate a failed/incomplete collection to partial/exit 4 after cleanup. Individual observed refusals or timeouts can remain recorded facts without pretending that a failed collector completed.

8. **should-fix — Stage C does not establish a non-IP control channel and can lose the question entirely.** `scripts/s11-0-probe.sh:359`, `:372`, `:382`, `:407`, `:1526`, `:1626`, `:1982`; `docs/s11-0-probe-runbook.md:49`.

   **Principle: device/keyword presence is not an end-to-end channel.** A virtio network device produces `virtio=present`; an ordinary terminal can produce `serial=present`. Neither shows a usable host-to-this-guest transport. Failed or timed-out `ioreg`/`system_profiler` queries are ignored and can be reported as blocked/absent. An exit-zero `tart exec ... true` while IP networking is still available does not reveal whether Tart used IP internally. `--stage all` exits before C if B loses SSH, exactly when independent control matters most.

   **Minimal fix:** delete the generic hardware/terminal scans and keyword-presence classifications. Make H1 investigation independent of SSH success: retain concise, bounded Tart help facts, document the transport from a reliable local source, and, if a candidate exists, perform a fixed round trip with its IP independence established. Otherwise explicitly report H1 unknown/unmeasured. Do not add a new channel implementation or open a gateway service to make this probe succeed. The runbook's “do not infer H1” caveat is correct, but leaves the third question unanswered.

9. **should-fix — A normal macOS symlinked Softnet installation can fail precheck; the checked binary is not tied to the run.** `scripts/s11-0-probe.sh:1136`, `:1156`, `:1225`, `:1494`.

   **Principle: validate the executable that will actually be used.** For a common installation where a prefix's `bin/softnet` is a symlink to a root-owned SUID executable, `ls -l` inspects the symlink itself. The mode is `lrwx...`, so the valid executable is rejected as not SUID. This is a concrete macOS launch blocker, not a Bash syntax issue. Conversely, `--softnet` only selects a file for this check; nothing passes that choice to Tart or proves Tart uses it. A readable SUID file elsewhere can satisfy precheck while Tart's own Softnet lookup fails or selects another installation.

   **Minimal fix:** resolve/follow the installed executable and check numeric ownership, executable status, and SUID on the target using macOS-supported operations. Validate the executable Tart actually selects; remove the override if Tart cannot honor it. The stubs should include a symlink and a mismatch, rather than synthesizing an `ls` line for any pathname containing `softnet`.

10. **must-fix — Privacy filtering does not cover hostname content or live clone diagnostics.** `scripts/s11-0-probe.sh:573`, `:971`, `:1047`, `:1928`, `:1450`, `:749`; `docs/s11-0-probe-runbook.md:49`.

    **Principle: retain only required facts, not arbitrary host strings.** `hostname -s` is written to both reports after a character filter. A hostname containing the owner's username, household name, or hardware serial remains intact; the filter only removes IPv4 patterns and punctuation. That violates the requested no-usernames-beyond-`eval`/no-hardware-identifiers rule. The runbook explicitly permits hostname, so its privacy promise is weaker than this task's requirement. Clone stdout/stderr also inherit the terminal through `run_bounded`; a Tart failure can print host paths and account names directly, bypassing report sanitization. `--guest-user` can additionally print arbitrary usernames in the dry run.

    **Minimal fix:** delete hostname collection/report fields and the unnecessary guest-user customization; keep the fixed `eval` role. Capture clone diagnostics privately with an output cap and expose only an allowlisted error code/reason. Do not try to redact arbitrary text with increasingly broad regular expressions. SSH readiness output is already discarded, and guest-SSH stderr is suppressed in both host runner branches: I found no direct SSH-stderr-to-report leak. Guest hardware inventory output is not printed, but collecting it in temporary files is unnecessary and should be deleted with finding 8.

11. **should-fix — The unconditional verify hook runs a Linux-only harness, while CI does not run it at all.** `scripts/verify.sh:11`; `scripts/test_s11_0_probe.sh:363`, `:401`, `:458`; repository-root `.github/workflows/computer-use.yml:34`, `:100`, `:118`, `:179`.

    **Principle: use the intended platform's tools, and distinguish local checks from actual CI gates.** The production probe's shebang is `#!/usr/bin/env bash`; the runbook invokes `bash`, normally 3.2 on stock macOS. I found no `mapfile`, associative arrays, case-conversion expansion, `readarray`, GNU `date -d`/`sed -r`, or production GNU `timeout` dependency. Indexed arrays, here-strings, `sed -E`, and `date +%s` are not themselves Bash 3.2 blockers. Compatibility is still unverified because only Linux Bash 5.2 was executed, including the Linux `setsid` branch rather than the Mac Perl fallback.

    The **tests**, however, require GNU `timeout` and reset PATH to the stubs plus `/usr/bin:/bin`. Stock macOS has no such tool; even a Homebrew-provided timeout outside those directories is hidden. Calls can return 127 before testing the probe, and the first `verify.sh` step fails before Rust gates. Windows/MSYS process groups and signal behavior are unverified too. The 33.53-second Linux cost is modest; the platform dependency is the problem.

    No checked-in workflow invokes `verify.sh` or `test_s11_0_probe.sh`; the macOS/Windows/Linux workflow matrix runs its commands separately. Thus this hook does **not currently break those jobs**, but it also provides no CI coverage of the new script. Do not describe it as a passing cross-platform CI gate.

    **Minimal fix:** remove this one-off suite from the universal verification entry point, or explicitly scope it to its supported platform and add a deliberate Linux workflow step. Before the Mini run, verify the production path with `/bin/bash` 3.2 and the no-`setsid` fallback. If portable stub coverage is desired, replace the harness's GNU timeout dependency and test the actual target environment rather than adding an installation requirement to the owner run.

12. **should-fix — Several test names assert a much stronger property than the stubs establish.** `scripts/test_s11_0_probe.sh:53`, `:57`, `:80`, `:107`, `:129`, `:359`, `:407`, `:700`, `:733`, `:809`.

    **Principle: a safety test must be able to fail for the unsafe behavior it names.** The Tart stub has no VM inventory: clone always succeeds, delete accepts any matching prefix, and `keep-other-vm` is a text file that no stub consults. `assert_deleted_only_prefix` does not prove deletion of only resources created by this invocation. No case covers pre-existing prefixed VMs, clone partial failure, hanging version/list/IP calls, stop/delete failure or false success, repeated signals, PID reuse, or the Mac fallback. The TERM case waits for a boot loop containing quickly returning stub calls; it does not test interrupting a hung synchronous call. The hardcoded expected IPv6/DNS results also enshrine the classification problem in finding 4.

    Three concrete mutations of the probe that the current suite would miss:

    - Remove `-o BatchMode=yes` from the real `SSH_OPTS` array at `scripts/s11-0-probe.sh:1331`. The SSH stub ignores authentication options, and dry-run text is independent of that array.
    - Remove **only stage B's** `--net-softnet` at `scripts/s11-0-probe.sh:1494`. The stub ignores run flags; the runtime assertion checks the block/allow substring but not this B flag. Stage A's exact-line check remains satisfied.
    - Replace the TCP destination `"$host"` in `nc -z -w 2 "$host" "$port"` at `scripts/s11-0-probe.sh:178` with `127.0.0.1`. The `nc` stub does not classify destinations, so the TCP result matrix stays unchanged while the experiment measures the wrong machine.

    **Minimal fix:** replace permissive stubs with a small stateful inventory and strict argv/probe-target assertions. Prioritize collision/partial-creation ownership, hung calls, real SSH options, and exact A/B argv. Do not add more report-format assertions as a substitute for those cases.

13. **should-fix — The runbook overpromises duration, cleanup, and prerequisites.** `docs/s11-0-probe-runbook.md:7`, `:11`, `:13`, `:18`, `:30`, `:37`, `:46`, `:49`; `docs/adr/0018-tart-disposable-provider.md:209`.

The script does not directly execute Softnet, but Tart necessarily invokes it during Softnet-backed runs; saying it does not execute Softnet without that distinction is misleading. The ADR change accurately links artifacts as written/unrun and does not authorize execution. No personal LAN address/CIDR, timezone, proxy, or broadband details appear in the runbook; its owner-specific volume path is unnecessary operational customization and can become an explicit `--tart-home` example placeholder.

    **Minimal fix:** correct the claims after simplifying/fixing the implementation, document authorized-key readiness and the status of unmeasured questions, and give a consistent measured estimate plus the actual enforced total including cleanup. 14. **should-fix — Delete features before adding more lifecycle machinery.** `scripts/s11-0-probe.sh:31`, `:297`, `:334`, `:372`, `:486`, `:573`, `:708`, `:749`, `:784`, `:817`, `:850`, `:956`, `:1526`, `:1668`, `:1750`.

    **Principle: minimize the one-off experiment to ADR §10's three questions.** Prefer these deletions:

    - Delete `ioreg`/`system_profiler`, `/dev` terminal/vsock heuristics, and generic virtio/address-presence success/blocked results. They neither establish egress denial nor a private channel, and introduce hardware-data collection and another process runner.
    - Delete hostname collection, arbitrary guest-user/golden overrides for this fixed-golden task, and reusable clone-name overrides. Keep the safe fixed source and fresh per-stage destinations.
    - Delete the four near-duplicate host timeout runners in favor of one bounded subprocess primitive with explicit input/output handling; remove the separate guest capture runner with the inventory scans.
    - Delete the parallel Markdown statistics/report implementation and ad hoc general string sanitizer. Keep one small structured fact artifact and, if needed, derive its human rendering from that artifact.
    - Delete the separately maintained dry-run command implementation. Print the same launch description that is executed and recorded.
    - Delete generic command-word surveys, redundant ICMP/address inventory, and unrelated tunable CLI surface where they do not answer a stated question. Keep a fixed, short approved target list, explicit unknowns, and the narrow transport investigation. Do not replace deleted probes with LAN scanning or a new guard implementation.

    A reasonable replacement consists of fixed prechecks, fresh owned A/B clones with exact recorded argv, a small guest collector with observations and execution errors, an independent concise H1 check, and one bounded cleanup path. S11-0 need not implement the future provider, model endpoint admission, or a hardware inventory framework.

The existing script does use literal, quoted `tart stop "$name"` / `tart delete "$name"` arguments and validates a non-option prefix/suffix; I found no wildcard deletion, `eval`, `pkill`/`killall`, production `rm -rf`, sudo, PF/firewall edits, route/resolver mutation, model invocation, or graphics-enabled `tart run`. All actual run sites include `--no-graphics`. The production removals are `rm -f` of temporary files; the test suite's `rm -rf` paths derive from its `mktemp -d` root. The configured golden is excluded from clone/run/stop/delete names on the ordinary VM-control path. These positives do not cure the prefixed foreign-VM collision or stale-PID risks.

The EXIT trap is installed before cloning; it lives in the main shell, and its required ownership/report state is global rather than lost in a command substitution or a returned function's locals. It unregisters itself to avoid recursive EXIT cleanup. Successful A cleanup clears ownership before B, so the ordinary path does not delete A twice; failed deletion is retried on exit. There is no basis to blame an unfired local/subshell trap here. However, `set -e` is deliberately disabled/ineffective in many conditional function calls and cannot supply missing status propagation or resource ownership. Cleanup success currently rests on Tart exit status, not an authoritative post-delete absence check.

SSH is configured for `BatchMode=yes`, `IdentitiesOnly=yes`, and public-key authentication; no password/token is requested, printed, or deliberately persisted. No timezone/proxy/broadband inventory is collected. The default RFC 5737 endpoint is explicitly marked `endpoint_source=placeholder` with a not-approved-endpoint note in both reports and in the runbook; that handling is honest. A user-supplied documentation address is merely labeled `argument`, however, so argument provenance must never be treated as proof of a real approved endpoint. Preserve those limits and the explicit `not_run` status for all real infrastructure behavior until an owner-notified run actually occurs.
