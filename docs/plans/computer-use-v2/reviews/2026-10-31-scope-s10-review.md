Reachability matters: the executable scoped engine remains fake-only (`gcu-cli/src/scope/mod.rs:44`). `RealX` does not override `XServer::window_incarnation`, whose default is `None` (`gcu-driver-linux/src/x11/server.rs:98`); scoped live X11 windows therefore refuse. The issues below concern the new Linux library adaptation and its available API compositions; this report does not claim a currently enabled native-eval exploit. In particular, the AT-SPI-only library path can run without an XID, and synchronous X queries can block **before** the missing-incarnation refusal.

Must-fix, category (a), before merge:

1. **[P1; Stop/native-call ceiling] New synchronous evidence queries can prevent Stop and its timeout from being polled.** `gcu-driver-linux/src/driver.rs:748`, `:758`, `:295`, `:303`; `x11/scope.rs:36`; `x11/real.rs:178`, `:184`, `:191`, `:114`, `:119`.

   Schedule: compose a scope-bound live Linux driver with `ScopedDriver` on a current-thread runtime, as used by the CLI (`gcu-cli/src/lib.rs:105`). Another X client holds `XGrabServer`, or the X server stops replying. Poll scoped `window_geometry`, snapshot admission, or a window-filtering operation: `window_binding` calls `resolve_xid`, which synchronously waits for geometry replies; the later observation waits for `_NET_WM_PID` too. Latch Host Stop while that call is blocked. The runtime cannot poll the independent Stop task or the enclosing Tokio native timeout until the synchronous reply returns. This can exceed both the release-issuance budget and the five-second abandonment ceiling. The missing live incarnation does not help: it is consulted after these waits. No new scope-mutex cycle is needed for this schedule.

   Bound native metadata queries themselves and move blocking X work off the control runtime into cancellation-safe, bounded ownership. Keep release dispatch independent of that work; merely adding `tokio::time::timeout` around a future containing `.reply()` cannot preempt it, and an abandoned blocking worker must not retain the only release path. `InstanceEvidence` explicitly leaves query bounds to the implementor (`gcu-core/src/scope/model.rs:185`). Add a bounded stalled-query regression through the actual evidence entry point, with Stop/release and native abandonment observed independently. Preserve 100ms/500ms/5s/4750ms; do not increase them.

2. **[P1; manufactured continuity / same-window-id reuse] AT-SPI-only window evidence copies the registered incarnation instead of observing a live one.** `gcu-driver-linux/src/atspi/scope.rs:19`, `:25`; `driver.rs:763`, `:773`; `identity/scope.rs:604`, `:615`.

   Schedule: on the pure-X11 AT-SPI path, register P's exact accessible window path W with incarnation 5, with no X mapping for W. An initial direct `LinuxDriver::snapshot_tree` populates the bus PID cache through the production `admit_read` path; the public driver can then be wrapped in `ScopedDriver`. P destroys W and later exports a different, unregistered window at the same object path, while P's PID/start/boot remain unchanged. On the next wrapper admission, `window_binding` supplies **5 from the registration** to `oracle.atspi`; `admit_tree` does the same before and after traversal. All comparisons pass. The replacement's tree can be read and returned; `window_geometry` can also select its new metadata from `list_windows`. Reuse may happen well before admission, not just in the final OS check/use interval.

   Obtain a real lifetime/continuity witness and the current accessible-to-window relationship, or return no binding and close this route. An object path plus its bus owner's process identity is not a window incarnation. Never fill missing observed evidence from the expected registration. Test destroy/recreate at the same path with unchanged process facts, through `window_binding`, `snapshot_tree` and geometry. This is the same fabricated/cached-evidence class as S2 R1-2/R2-A2, not the owner's accepted macOS final check/use residual.

3. **[P1; foreign content read and false handle provenance] Only the tree root's owner is checked; every descendant is then attributed to that root's window.** `gcu-driver-linux/src/driver.rs:413`, `:455`, `:635`, `:637`; `atspi/bus.rs:128`; `atspi/tree.rs:175`, `:200`, `:218`; `identity/scope.rs:685`, `:687`, `:738`, `:753`.

   Schedule: use an admitted AT-SPI root in P, with the owner cache primed as in finding 2. Its `GetChildren` includes an embedded accessible `(destination=C, path=E)` belonging to an unregistered process, or an accessible from unregistered sibling window B in P. This is representable by the production child-reference decoder, which preserves a child's different bus destination. The ordinary walker follows E and reads its name/value/text before any E owner/window check. P's root remains unchanged, so the post-read root check succeeds. `seal_tree` records E under the requested root window without inspecting E's destination or parent/window; `element_binding` has no live observation and synthesizes E's owner from that seal's registered P. Core sealing consequently accepts the fabricated binding and can return C/B's content. Later semantic refusal does not undo this read or publication.

   Validate each node's bus owner/process instance and exact registered window relationship **before its first content query**, including cross-destination child references and same-process cross-window nodes. Recheck the producing evidence before returning/sealing; do not label an entire raw tree with the requested window after traversal. Refuse the observation when provenance is unavailable. Add foreign-owner and sibling-window canaries through the production traversal/sealing path, asserting zero foreign content queries as well as no returned payload/handles. A root-only pre/post check is insufficient under ADR §2 even with a trusted fixture root.

4. **[P1; missing production path / misleading positive coverage] Scoped AT-SPI cannot bootstrap through core, and semantic delivery has no production source of the live evidence it requires.** `gcu-driver-linux/src/identity/scope.rs:575`, `:630`, `:708`; `driver.rs:384`, `:413`, `:748`; `perform.rs:283`, `:288`; `atspi/scope.rs:50`, `:157`.

   Schedule A: bind a fresh native AT-SPI-only driver and put it directly into `ScopedDriver`, with a correctly registered allowed process/window. Core needs `window_binding` before calling the inner snapshot (`gcu-core/src/scope/driver.rs:279`). The AT-SPI PID cache is empty; its only live refresh is inside that snapshot's `admit_read`. Admission therefore fails before the refresh can run. Listing apps/windows does not refresh this cache either.

   Schedule B: prime the cache and successfully obtain an allowed tree using the direct driver path, then pass **that tree's actual root handle** to scoped `perform(Press)`. `admit_handle` requires `oracle.handle(key)`. The handles map starts empty, and its only insertion function, `set_handle`, is `#[cfg(test)]`; no production observation populates it. Every scoped semantic action therefore refuses, including SetValue/SelectText/ScrollElement and TypeText with a focus handle. This is fail-closed, but does not implement the card's promised allowed AT-SPI delivery.

   Wire real, bounded owner/window observations into metadata admission and semantic delivery, without requiring an earlier unwrapped content read. Carry the immutable admitted process/window context through each asynchronous AT-SPI operation and verify at the actual mutation sink, after preparatory proxy/action queries. Do not fix liveness by accepting the read-time seal as current ownership or by allowing a missing scoped binding to mean unscoped. If this route remains unprovable, explicitly mark it unavailable and narrow the card's implementation claim rather than declaring semantic support.

   Existing tests hide the gap: `atspi/scope.rs:132`/`:144` inject observations with a test-only writer; the test named `scoped_tree_and_press_stay_inside_the_admitted_owner` manually injects the app PID at `:181` and presses unrelated handle 11 at `:213`, demanding refusal. It never attempts a successful action on the returned root handle. Add an allowed-positive observe→actual-handle→action control through `ScopedDriver`, alongside missing/crossed/reused-owner refusals. Do not treat a post-action core owner check as prevention of an unauthorized action.

5. **[P1; discovery metadata provenance] `app_instance` proves the registered PID is alive, not that it owns the discovered application.** `gcu-driver-linux/src/driver.rs:717`, `:722`, `:729`; `identity/scope.rs:209`, `:217`; `gcu-core/src/scope/driver.rs:184`, `:187`.

   Schedule: register an AT-SPI well-known bus name N while P owns it; `ScopeWindow::try_new` permits such a name and does not require a non-transferable unique name. P releases N but stays alive with the same start/boot; an unregistered C acquires N and exposes its application through that name. Live discovery queries N and obtains C's name, PID and executable identity (`gcu-driver-linux/src/atspi/discovery.rs:42`, `:50`, `:55`). The wrapper filters that AppInfo with `app_instance`, which uses only its id N to look up **registered P**, re-reads P, and returns P's instance. It never compares the discovered PID C or re-establishes N's owner. Core therefore keeps and returns C's metadata as an allowed app; no window proof, cache priming, content read or input is required. This schedule uses the accepted bus-name API, not a claim that ordinary AT-SPI deployments always choose transferable names.

   Bind registration and queries to a bus-authenticated unique owner and verify the actual discovered source's process instance; reject transferable/unresolved names if their ownership cannot be carried safely. At minimum, contradictory discovered PID evidence must refuse instead of being replaced by the expected PID. Ensure the name/image metadata belongs to that verified source before publication. Add a production-entry discovery regression with N changing owner while P remains alive, and an allowed positive control; require no C name/path/hash/PID in list or resolve output. RealX's missing incarnation does not protect this app-only path.
