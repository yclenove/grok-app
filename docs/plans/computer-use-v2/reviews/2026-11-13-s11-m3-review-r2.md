## Findings

### F1 — P1: the new preflight turns a conforming guest publication into a protocol breach

**Evidence:** `mailbox/slots.rs:568` and `:573` run preflight before the selected message lookup. `:1077` collects the bounded directory names, then `:1086` calls `stat_name` separately for each name. `stat_name` maps `ENOENT` unconditionally to `Breach::Identity` at `:800`. The `?` at `:573` propagates this as `FailedRead`; it never reaches the transient absence path at `:584`/`:593` or its counter increment at `:940`.

A normal schedule is sufficient:

1. The guest exclusively creates, writes, and syncs `guest-write/inventory.msg.tmp`.
2. Host preflight enumerates that allowed temp name and finishes `list_limited`.
3. The guest renames the temp over the pre-created `inventory.msg`.
4. Host preflight performs no-follow `fstatat` on the enumerated temp name. It now gets `ENOENT` and returns `Breach::Identity`.

The layout is valid throughout this schedule. The target publication is atomic on an ordinary local filesystem; the disappearing source name is required by the agreed tmp lifecycle. The host can therefore fail a valid inventory poll, or a poll of another slot in the same directory, during routine publication. The same unconditional mapping also bypasses counted Pending when a listed `.msg` returns transient `ENOENT` during preflight. No malformed bytes or replaced directory are necessary. This contradicts the transient-visibility contract, and a caller following the failure-closed API will terminate the attempt.

This is a regression introduced by the R13 repair. `guest_publication_source_is_created_exclusively` (`mailbox/tests/slots.rs:375`) performs the rename before reading, so it cannot exercise the window. `directory_whitelist_stops_at_allowance` (`:541`) checks static bad entries and missing temps, not a permitted entry disappearing between enumeration and metadata lookup.

**Minimal fix:** distinguish message-directory preflight from directory-identity checks. Tolerate `ENOENT` for an allowed optional `.msg.tmp`; for an allowed `.msg`, defer absence to the selected-slot lookup or return counted Pending after confirming the directory chain. Keep missing/replaced directories, unknown names, links, and special objects as breaches. Do not rescan to stability or expand the enumeration bound.

**Required regression:** add a deterministic seam after enumeration and before the entry's `fstatat`; rename an allowed guest temp over its message there and require a successful stable read or Pending, never `FailedRead`. Also inject `ENOENT` for a listed selected message and verify Pending with retained retry evidence. Include the joined `poll_guest` path.

### F2 — P2: R8's source-scan exemption is still escapable through ordinary module paths and distinct Unix filenames

The old suffix/checkout-ancestor exemptions are removed, but the replacement still does not enforce the intended source and compilation boundary.

**Evidence, module imports:** `production_path_reuses_exempt` at `crates/gcu-eval/tests/tart_offline.rs:1117` checks only whether each parsed attribute directly names one of five exempt files (`:1124`). It does not resolve an inline module's directory and its descendant module declarations. For example, adding this to `mailbox/mod.rs` leaves the existing `#[cfg(test)] mod tests;` intact:

```rust
#[path = "tests"]
mod live {
    mod support;
}
```

Rust resolves `live::support` to the exempt `mailbox/tests/support.rs`, with the same enclosing depth as the test module. The checker sees only the directory `mailbox/tests`, which is not an exempt file, and returns false. Its filesystem/environment exemption for the imported source still applies. The separate gate at `:1099` checks declarations named `tests`, so it does not reject this production alias.

Direct imports also evade the parser using a legal raw string, such as `#[path = r"tests/mod.rs"] mod live;`: `path_attributes` at `:1164`/`:1165` accepts only an immediately quoted ordinary string and **breaks** on the raw form, omitting that attribute and all later ones. These are ordinary Rust module forms, without aliases for forbidden API tokens. They invalidate the explicit controller requirement that production imports must not reuse exempt sources. This is a regression-guard defect, not a claim that the current production module already imports these test files.

**Evidence, file classification:** `rel_under` at `:1066` and `scan_exempt` at `:1073` both call `normalize_rel`. Its `:1086` splits on both slash and backslash. On Linux and macOS a backslash is a valid filename byte, not a path separator. A distinct source file with relative name `mailbox\sys.rs` is therefore granted the unsafe exemption for `mailbox/sys.rs`; likewise `mailbox/tests\support.rs` gets the filesystem/environment exemption for `mailbox/tests/support.rs`. `walk` at `:1193` still collects such `.rs` files. Thus the classifier is not exact for the requested Unix targets. The new classifier tests at `:981` cover normal slash paths and checkout ancestors, but none of these cases.

**Minimal fix:** compare filesystem paths after stripping the scan root using exact platform `Path` components; do not reinterpret backslashes or lossily normalize real filenames into an allowed source. For production module imports, either reject path attributes except the exact existing `mailbox/sys.rs` declaration, or resolve supported Rust module/literal forms and reject unsupported forms instead of silently skipping them. Include directory-valued inline module attributes in that policy. Preserve the actual `#[cfg(test)]` gate and all process/wait restrictions.

**Required regression:** reject the inline-directory import and raw-string import above, including a raw attribute followed by an ordinary forbidden import. Classify literal backslash filenames as non-exempt on Unix. Retain the valid sys file, five known test files, nested lookalikes, and checkout-ancestor cases.

## Filesystem and unsafe audit

The full file stamp is now retained for each host placeholder/last publication (`mailbox/slots.rs:207`, `:547`). `same_file` at `:986` compares dev, inode, nlink, size, mtime seconds/nanoseconds, ctime seconds/nanoseconds, and kind. It is used for destination authorization (`:825`), source-name versus source-FD validation (`:872`), publication-name versus FD validation (`:893`), and pre/post read FD stability (`:930`). The final read name check verifies dev/inode against the still-open file, as ADR §3 step 6 requires. This is still a sequence of metadata observations, not an atomic filesystem snapshot; the ADR's final check/use and guest in-place modification limitations remain.

All directory levels actually traversed by a read/publication are checked against their recorded identities and opened FDs through no-follow `fstatat`. The volume-root FD itself is checked by `fstat`/FSID (`mailbox/slots.rs:672`); its trusted mounted-parent relationship remains the caller's precondition. The destination recheck has no write/fsync window before rename. Source FDs remain alive through verification, and directory/file FDs are local to each call.

The new enumeration uses raw name bytes from libc, bounded to 3, 9, or 15 non-dot entries for the export, host-write, or guest-write respectively. `.` and `..` are excluded. It neither decodes names as UTF-8 nor sorts/recurses/retries for a stable listing. Each successful listing's entries are looked up without following links. The defect is the classification of an allowed disappearing entry, not an unbounded or string-normalized mailbox whitelist.

**No new unsafe memory-safety/ABI defect found for Linux or macOS.** The new unsafe sites were traced through ownership and error paths:

| New boundary in `mailbox/sys.rs` | Assessment |
| --- | --- |
| `:303` — `fcntl(F_DUPFD_CLOEXEC)` | On success returns a new owned duplicate; the variadic minimum descriptor is a `c_int`. Production callers supply newly opened directory FDs. The duplicate shares the directory offset, but each production preflight receives a fresh directory open and lists it only once. No cross-poll cursor is retained. |
| `:308` — `fdopendir` | Receives the duplicate, not the borrowed original. Successful adoption transfers closure to the unique `DirHandle`; failure leaves the duplicate for the explicit `close` at `:197`. No double adoption/close found. |
| `:206` — `readdir` | Uses a live local DIR stream. Null return is distinguished from EOF using errno cleared before each call (`:203`); EINTR retries, other errors fail. A returned entry is copied before the next `readdir` or stream destruction. |
| `:317` — `dirent.d_name` / `CStr::from_ptr` | The only call is on the non-null pointer just returned by `readdir`. Linux/macOS libc supplies a NUL-terminated name, and the bytes are copied while that entry remains valid. No cast between platform `dirent` layouts or use-after-next-read found. |
| `:295` — `closedir` | The non-cloneable private handle owns the only adopted DIR pointer; Drop closes it once and nulls its local pointer. Return/error paths drop the handle. |
| `:197` — failure-path `close` | Runs only after failed `fdopendir`, which did not consume the duplicate. It does not retry close or close the caller's FD. |
| `:323`, `:332`, `:337` — errno access | Writes zero to the current thread's libc errno cell using macOS `__error` or Linux `__errno_location`. The live thread-local pointer and scalar write are valid on these two targets. No broader Unix portability claim is made. |

The earlier `stat`/`statfs`, read/write, open/openat, renameat, fsync, and FSID-copy boundaries remain sound under the round-1 Linux/macOS assumptions. Existing mode promotion for variadic openat remains present (`mailbox/sys.rs:348`), and new test-only forced reads are entirely cfg(test) (`:143`, `:252`). Enumeration creates no new process, thread, mount, or real channel. Ordinary disk/libc blocking and EINTR wall-clock bounds still depend on the external provider deadline/kill/reap owner, as already documented by the ADR.

## Scope and remaining boundaries

The fix does not wire `machine/`, `GuestChannel`, or admission, add a dependency, or add an enable switch. `GUEST_CHANNEL_VERSION` is still 1 (`crates/gcu-eval/src/disposable/tart/guest.rs:22`), and the seven-method trait is unchanged (`:52`). The supplied tests establish exercised offline behavior, not live guest/host export isolation or virtiofs timing.

M4 still owns one-effect-in-flight scheduling, correlation/retention/consumption of inventory result rows, normalized side-effect completion, cumulative 128 KiB poll accounting, and real lease age/gap/deadline enforcement. Rejecting direct side-slot terminals closes R6 without prematurely implementing those transitions. Binding bytes remain structurally bounded and publish-once but opaque to this layer (`mailbox/slots.rs:347`, `:498`); the future typed binding producer must enforce its closed schema and no-secret content before publication.

The remaining requested changes are F1 and F2. No implementation fix or commit was made during this review.
