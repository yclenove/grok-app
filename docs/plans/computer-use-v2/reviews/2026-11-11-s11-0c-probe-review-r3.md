# S11-M2a independent code review, round 3 (final) — 2026-11-11

**Verdict: MERGE-AFTER-FIXES. Do not run HEAD 04d7eb03 on the shared Mini as-is.** The structural decision is sound: keep the existing bash host driver and the small Rust measurement core. Findings 1–7 concern concrete hangs, host resource exposure, or silent measurement/evidence errors. They need direct controller fixes; another architecture or fourth review round is unnecessary. Findings 8–11 are should-fix under the requested final-round severity bar.

Reviewed branch `cu2/s11-0c-probe`, HEAD `04d7eb03`, after reading both earlier reports and ADR 0019 §§3/5. References below are relative to `computer-use/`; `src/` abbreviates `tools/s11-mailbox-probe/src/`. The six Rust files contain **999 production lines and eight tests**, counting lines before each test module. Deleted Rust orchestration is not a second implementation to repair. C4/C5/C6/C7/C9/C10 and the deferred round-1 volume findings are outside this review.

This was a read-only code review except for this report. No network, Cargo, test-suite execution, VM operations, source changes, or commits. Verification consisted of `bash -n` on both scripts, source/diff inspection, production/test counts, and an in-memory bash EOF/read check. No Mini behavior is claimed. The existing shell suite writes scratch files and launches helpers, so it was inspected rather than run under the instruction to write only this report.

**Numbered findings**

1. **must-fix / P1 — The apparent subprocess bound still ends in an unbounded wait, and the controller can block outside it.** `scripts/s11-0-probe.sh:50`, `:63`, `:79`, `:611`, `:823`, `:884`; `src/run.rs:555`, `:563`, `:575`.

   **Failure scenario:** a host measurement worker or Tart command blocks in filesystem/kernel IO. After TERM and the short grace, `term_kill_reap` sends KILL and then executes unconditional `wait`. SIGKILL does not guarantee that an uninterruptible process has exited. The shell can remain there indefinitely, with cleanup signals ignored. Separately, `wc`, hashing, result-slot opens/reads, the export audit, and report IO run synchronously in the orchestrating shell, outside `run_bounded`. A blocked one prevents that shell from checking its deadline or stopping its VM. Rust still has its own `dscl` subprocess implementation: its timeout does blocking `child.wait()`, and its post-exit stdout drain has no deadline. A human watching the terminal and manual recovery instructions do not enforce a bound on these paths.

   `PROBE_DEADLINE` is an aggregate 1500-second work bound, not the ADR's per-load bound. C1 starts a new 50/60-second allowance for writer and reader on each side, and M inherits clone=180 seconds and cleanup=90 seconds. There is no single load end ≤60 seconds or first-cleanup end ≤60 seconds. The five-second SSH finish allowance starts after both host commands. These are inherited or newly connected properties, not regressions claimed in A/B/C.

   **Minimal fix:** supply one small automatic stage-M supervisor outside the process that performs mailbox/local FS IO. It must own an isolated job/process group and the exact clone receipt, retain control without reading the mailbox, enforce original absolute load/attempt/cleanup ends, and terminate without joining a stuck worker. After KILL, poll only until the reserved end; call `wait` only after the shell has established that its job is no longer running. Unconfirmed termination means quarantine, no delete/export cleanup or next attempt, and manual recovery of the exact recorded resource. Bound the supervisor's own Tart control calls too. Clamp M's phase/command caps to ADR §5/§2 without changing A/B/C's selected workload. Remove or externally contain C8's second runner rather than growing a parallel Rust orchestration layer. An existing controller wrapper is sufficient **if it actually implements these properties and is included in the run receipt**; no such automatic wrapper was supplied here.

2. **must-fix / P1 — Host measurement exit/timeout failures are discarded in favor of whatever result file exists.** `scripts/s11-0-probe.sh:817`, `:821`, `:822`, `:827`, `:833`, `:840`; `src/run.rs:179`; `src/io.rs:267`.

   **Failure scenario:** the Rust host reader renames a `verdict=ok` result into place, then its result-directory fsync fails. `finish` correctly exits 1, but bash discards `RB_STATUS` and accepts the already-visible result. C2 has the same path with `not-ack`. A killed/timed-out host process can likewise leave a readable success record. In C1 the writer's status is overwritten by the subsequent reader command; failure while finalizing the writer can disappear when the reader overwrites `result-host`. `note_guest_ec` checks only the SSH exit. This can falsely certify a completed experiment even though its own command failed. Finding 8 currently masks the normal integration path; fixing that format error alone exposes this bug.

   **Minimal fix:** snapshot each host command's exit, timeout, abort and overflow flags immediately. All required host commands and the bounded SSH workload must complete successfully before an `ok`/`not-ack` file can authorize completion. Preserve an observed integrity `failed` verdict when a later operational error occurs; otherwise operational uncertainty produces `unknown`. Require the final C1 record to be the reader result with its required peer/count evidence, so an old writer record cannot stand in for a reader that never completed. Apply the same rule to result-publication failure and C2 observation failure. C8's deliberately unknown exit remains an expected non-success measurement result.

3. **must-fix / P1 — A syscall that returns after the command's absolute end can still produce success.** `src/run.rs:244`, `:255`, `:298`, `:338`, `:367`, `:390`, `:408`, `:455`; `src/run.rs:179`.

   **Failure scenario:** the last C1 publish starts before the 50-second end and its fsync returns just after it. The loop finishes, writes an `ok` summary/result, and exits zero. The outer 60-second command allowance accepts it. C1 reader checks the end only at the top of a pass, so eight slow reads and summary IO can cross the end and still pass. C2 host checks once before all observation IO; C2 guest does not check after its last data operation or before its success progress/result publication. Thus a soft timeout checked before IO is being reported as an enforced absolute deadline.

   **Minimal fix:** pass the original end through the measurement operations and check it after every returning operation, between reads, and before publishing/accepting a terminal success. Discard late success as `unknown/deadline`, retaining any actual integrity failure already observed. Include terminal record publication in completion: if it crosses the end, the process must return nonzero and the driver must reject the late record (finding 2). The independent bound in finding 1 handles syscalls that never return; these postchecks handle ones that return late. Do not create a fresh end at summary/finish.

4. **must-fix / P1 — C1's `ok` no longer measures the declared latency/rename experiment.** `src/run.rs:150`, `:233`, `:281`, `:345`; `src/io.rs:171`, `:183`, `:221`, `:236`; `scripts/s11-0-probe.sh:1007`.

   **Failure scenario:** both writers publish all eight separate `f-N` files, then each reader inspects the surviving peer files and its writer summary. A host-to-guest visibility delay of several seconds can be completely missed because the reader starts after its own batch writer. No per-publication visibility end ≤3 seconds, sample round trip, first-complete-read timestamp, or complete publication/read slice is measured or judged. A slow but eventually successful exchange can be `ok` despite the ADR's ≥2-second round-trip obstruction. `lost=0` is a constant, not an observation of updates to a slot. Separate immutable final files establish surviving-byte correctness, but do not observe old/new replacement transitions.

   Writer clocks are retained in `summary-*`, while `result-*` is replaced by a reader clock with write/fsync/rename fields absent. The final JSON copies neither record's measurements/counts. Even the operation clocks omit fstat/verification and failed opens; `fsync_us` includes a subsequent fstat, and `open_us` excludes the fstat. None is a measurement of the complete ≤100ms IO slice. The result therefore cannot support the complete C1 observation described in ADR §5.

   **Minimal fix:** either restore the small deterministic, overlapping per-sample publication/observation protocol with local visibility/round-trip and complete-call timings, or explicitly mark those C1 observations `not_measured` and the overall C1 result `unknown/partial-coverage`. Do not issue an unqualified C1 `ok` for the reduced surviving-files check. Report actual per-direction counts and both writer/reader measurements from the mailbox, with unmeasured fields absent/unknown. Time enclosing IO calls for the slice maximum, retain real sub-operation timers with accurate labels, and do not invent loss or timing values. This does not require production leases or M7 transport work.

5. **must-fix / P1 — Same-FD stability does not bind the final name or publication source.** `src/io.rs:107`, `:213`, `:240`, `:250`, `:258`, `:262`; `src/run.rs:122`.

   **Failure scenario:** after `read_file` opens `guest-write/f-1`, the guest renames that file to another name, preserving its nlink and timestamps, and installs torn bytes at `f-1`. Both fstats of the retained old FD match, its bytes are valid, and C1 can return `ok` without ever checking the currently named object. Similarly, a guest can move the exported temporary source aside and substitute another ordinary inode before `renameat`; `publish` checks the retained original FD and separately compares the named file's bytes, but never compares the named inode to the retained source inode. A same-content substitute can be credited as publication of the original source. An open child directory moved/replaced under its original name has the same disconnected-name issue. Dev equality alone does not detect any of these same-filesystem changes.

   **Minimal fix:** retain the opened dev/inode and verify the fixed name through the same retained parent FD after reads; compare it to the actual read FD. Compare the source name to the retained source FD before rename and the final name to that same FD afterward. Include ctime in read-before/after snapshots. Record/check child directory dev/inode and its parent-name association instead of accepting an ordinary same-device replacement as a new baseline. Refuse replacements as integrity failure/unknown rather than retrying to success. Use a protected, unexported source if source-name exclusion cannot be established. These are narrow identity checks for this ordinary-directory experiment, not a request to reinstate volume orchestration or claim authentication against an arbitrarily malicious filesystem.

6. **must-fix / P1 — The whitelist audit is unbounded before its count check and can miss unknown names containing newlines.** `scripts/s11-0-probe.sh:881`, `:884`, `:886`, `:899`, `:938`, `:979`.

   **Failure scenario:** an unexpected guest process creates many entries, or continues directory churn after VM termination was not established. `find` writes the entire listing to the host temporary file before the shell checks its 32-entry cap. It has no timeout or output cap; the host can exhaust disk space or hang in this cleanup path. Independently, an unknown file whose actual name is `result-host` followed by a newline can evade the audit when the legitimate `result-host` exists: `find -print` splits the unknown name into the legitimate path and a blank line, and the loop accepts the former and skips the latter. The unknown object remains, but cleanup can label the directory `retained` and allow the next C2 attempt.

   **Minimal fix:** run enumeration under the bounded command/output machinery, using NUL-delimited names and checked complete output; overflow, too many entries, an unsupported query, or any parsing/read error means quarantine. Reject a name as one complete byte string, and do not skip blank fragments from a line protocol. Prefer an early whitelist-size-plus-one enumeration stop where supported. Establish successful VM/workload termination before auditing/removing any export entries; otherwise retain/quarantine immediately. Continue to unlink only the host-owned fixed boundary file and rmdir empty known directories, with no recursive fallback. The outer supervisor must also cover audit FS stalls.

7. **must-fix / P1 — Only the last report rename is checked; failed intermediate evidence writes can disappear from a successful report.** `scripts/s11-0-probe.sh:954`, `:958`, `:983`, `:1003`, `:1018`, `:1036`, `:589`, `:598`, `:601`.

   **Failure scenario:** `$WORKDIR` runs out of space while writing `stage-M.json`, while `--out` is on a filesystem with space. `m.agg` already contains `not-ack`; the failed `save_stage_m` is ignored. The subsequent report builder can successfully copy an empty stage file, finish valid JSON with `stages:[]`, rename it, and exit zero. A failed row append followed by later successful appends is another path: `fold_m` accepts the surviving two `not-ack` rows because it never requires exactly the three planned boundaries. Individual `cat`/printf failures inside `write_report` can also be masked by its final successful printf. Checking nonempty final output and the final `mv` does not check the earlier writes.

   **Minimal fix:** propagate every row/argv/cleanup/stage write and every copied report fragment. An IO-failure flag must survive to a nonzero final exit even if later writes succeed. Require exactly the planned case/boundary rows, each once, before completion; never fold a shortened file into success. Publish a stage only after all its writes succeed, and make a complete required stage a prerequisite for final report success. Preserve the useful existing final-rename failure check. Test a failed row write and a failed stage write, not only a failed final `mv`.

8. **should-fix / P2 — Real Rust records have no newline, so the bash reader rejects every healthy record.** `src/run.rs:150`, `:163`, `:166`, `:173`, `:177`; `scripts/s11-0-probe.sh:797`; `scripts/test_s11_0_probe.sh:1191`, `:1194`.

   **Failure scenario:** `store` publishes `line.as_bytes()` without a trailing newline. Bash `read` fills `line` but returns 1 at EOF; `|| return 1` discards it. Real C1/C2 therefore become `unknown/probe-failed`; C8 loses `single-principal` or `mapping-not-measured`. The stub emits a newline, hiding the mismatch. An in-memory reproduction here returned `read_status=1` with a nonempty 39-byte record. This fails closed, which is why it is not classified as a safety blocker by itself.

   **Minimal fix:** define one exact record framing policy. Either include the newline in Rust's capped publication, or accept a nonempty EOF-terminated record in bash while rejecting additional records/trailing bytes. Feed actual Rust-format bytes to the orchestration fixture. Do not make the parser broadly permissive to fix EOF.

9. **should-fix / P2 — C2 error records invent attempt/rename counts, and summary parsers accept incomplete/contradictory schemas.** `src/run.rs:119`, `:194`, `:345`, `:381`, `:457`, `:480`, `:509`; `scripts/s11-0-probe.sh:799`.

   **Failure scenario:** C2 succeeds at publish 1 and fails during publish 2. The guest falls back to all-zero counts, while the host's unknown result says `attempted=3` and uses the visible count as `renamed`, without having received trusted progress. A host observation is not proof of how many guest operations were attempted. Separately, `field` selects the first matching token, ignores duplicates/trailing fields, C1 does not validate `torn`/`lost`/reason, and C2 does not validate all progress fields such as role/part/visible. A contradictory C1 summary carrying the correct digest and `torn=1` is accepted. Bash checks only verdict/reason, without version/op/role/count binding.

   **Minimal fix:** count attempted work before dispatch, preserve partial counts on guest error, and report unobserved guest counts as unknown on the host. Keep planned, attempted, renamed and independently visible distinct. Use a tiny exact versioned record decoder with required closed fields, uniqueness, whole-record consumption and consistency checks; no general JSON framework. Successful C2 file-sync's `3/3/2/2` is otherwise correctly represented, and its third part is now validated against the exact expected frame. Existing unknown/error outcomes keep most malformed progress from becoming completion; the remaining parser hardening should not expand the experiment.

10. **should-fix / P2 — Quarantine exit-code precedence does not match the stage-M contract.** `scripts/s11-0-probe.sh:938`, `:973`, `:1118`; `docs/s11-0-probe-runbook.md:108`.

    **Failure scenario:** C8 returns its expected unknown, or a probe fails, and export audit also finds an unknown name/link. Both collection and cleanup failure flags are set. `decide` returns 4 before checking cleanup, although the M contract says quarantine exits 5. The report still has quarantine and the exit is nonzero, so this is not a silent success or destructive cleanup defect.

    **Minimal fix:** give stage-M quarantine an explicit exit-5 precedence, preserving measured failure/unknown in the case row. Keep A/B/C's existing precedence unless intentionally changing their contract.

11. **should-fix / P2 — Argv serialization silently drops a valid share argument containing spaces.** `scripts/s11-0-probe.sh:511`, `:956`.

    **Failure scenario:** `--out '/Users/eval/lab results/run1'` is accepted and passed correctly to Tart as one array element, but `json_list` drops `s11mbx:.../lab results/.../mailbox` because of its character filter. The receipt contains `--dir` without its value. This loses replay/audit information, although it does not alter the actual launch or authorize broader sharing.

    **Minimal fix:** JSON-escape accepted argv elements exactly, or reject unsupported output-path bytes before creating resources. Never silently remove an actual argument from its receipt.

**Highest-value missing tests**

The eight Rust tests cover SHA vectors, frame corruption, static leaf type/size refusal, an already-expired writer, summary absence/static torn input, ordinary C2 surviving bytes/part corruption, and a pure C8 count/policy fixture. They do not establish the new orchestration's integration or timing boundaries. Prioritize these small boundary tests over more normal local exchanges:

1. **Actual record bytes across Rust/bash:** EOF without newline, exact terminal reader/op/count binding, duplicate/trailing record rejection, and the real C8 unknown reason. The current newline-adding stub and its always-successful SSH stub conceal the integration failure.
2. **Failure after publication:** host result rename succeeds but directory sync/terminal exit fails; writer fails before reader; command killed after an apparent success record appears. Assert no `ok`/`not-ack` completion and preserve prior integrity failure.
3. **Deadline crossing during the last operation:** delayed last publish, last frame read, summary read and result fsync, all inside the outer command timeout. Assert unknown/deadline, no fresh deadline, and no late success. Separately exercise the automatic supervisor with a harmless TERM-resistant child and an IO worker it deliberately abandons without blocking reap.
4. **Object/name replacement:** rename an opened frame aside without unlinking it, install a different inode at the name, replace an open child directory, and substitute the temporary source. Assert no accepted replacement publication/read. Existing leaf symlink/hardlink tests do not cover these windows.
5. **Whitelist/report error paths:** NUL-framed newline names, whitelist-size-plus-one entries, enumeration overflow/timeout, failed VM termination, failed row append and failed stage publication. Assert quarantine/no advance or nonzero report failure, and require all three C2 rows. These belong in the bash boundary tests, not a new Rust host framework.
6. **Measured coverage:** a delayed peer with valid final bytes must not receive a complete C1 latency pass; distinguish unmeasured latency from successful integrity observations. C2 write-2 failure must preserve actual attempted/renamed/visible counts. Successful local test files alone cannot establish virtiofs latency or durability.

After these direct fixes, the controller can run the corrected approved artifact under the recorded lab conditions. The evidence remains ordinary-directory **DEFAULT-network / mechanics-only**; volume behavior, production liveness/Stop, writer isolation, actual two-principal mapping and real-eval admission remain unproved.
