**MERGE-AFTER-FIXES**

Independent static review of `cu2/scope-s9` at `01d8a305`: commits `a05630af`, `01d8a305` against `origin/feat/cu-v2` (`e492bed5`). Judged against ADR 0017 §1–§3, §5's S9 and identity/lifecycle rows, ADR 0013 and its pointer-gate addendum, and the S1/S2/S3 review history. Paths below are relative to `computer-use/crates/`. These are source-level schedules, not executed reproductions.

The new equality helpers reject unequal supplied claims, and the native process probe reads the full creation FILETIME through an opened process handle. Those properties do not establish that the claims describe the element, recipient, or queued native operation actually used. The findings below recur in the earlier reviews' owner-proof, check/use, publication, boot-identity, and unscoped-compatibility classes.

Must-fix, category (a), before merge:

1. **[P1] Tree contents and element evidence inherit the requested window's identity without proving the UIA element's owner.** Changed boundary: `gcu-driver-windows/src/driver.rs:378`, `:397`, `:400`; producers: `src/uia/observe.rs:62`, `:65`, `src/uia/ffi/identity.rs:26`, `src/uia/ffi/mod.rs:181`, `src/uia/tree.rs:116`.

   Schedule: register only window A of process P. A hosts a child HWND/UIA fragment belonging to an unregistered process Q at the same integrity level; cross-process child windows can remain under A. Read A. Traversal obtains the child's cached name/value without calling the new `owner_pid`; `Observer::bind` stamps every node with A's `WindowRef` and HWND. A remains unchanged, so the closing `scope_close` succeeds. During core sealing (`gcu-core/src/scope/guard.rs:182`), `element_binding` supplies **`Some(binding.owner().pid())`**, derived from A, as the purported element owner. It never resolves the node or asks its UIA source. Q's content and handle therefore pass as A's content. A same-process element moved into unregistered B also continues to receive A's binding from this evidence API while A remains live.

   Prove each native fragment's actual process instance and window membership before materializing its content, retain that provenance with the handle, and recheck the actual element when supplying evidence. Refuse an observation whose source cannot be proved; substituting the root's owner is insufficient. A post-tree check of A cannot repair this. The positive evidence test at `tests/scope_identity.rs:45` constructs an arbitrary `UiaElement` with no corresponding source node and expects proof at `:55`; it demonstrates this metadata-only acceptance, not a verified native element. Add a foreign-child canary through `ScopedDriver::snapshot_tree` and assert zero foreign content reads and no returned tree/handle.

2. **[P1] Native input adopts a foreign child recipient as its expected identity.** Changed checks: `gcu-driver-windows/src/input/ffi/mod.rs:175`, `src/input/mod.rs:199`, `:301`; actual admission: `src/input/ffi/mod.rs:194`, `:208`, `:249`, `:479`; helper: `src/scope_identity.rs:129`.

   Schedule: keep admitted A/P alive and place an ordinary EDIT child owned by Q under A. Issue a targeted coordinate click over that child, or targeted typing into that focused child. `State::resolve` finds it using child hit testing or `GetGUIThreadInfo` (`src/input/ffi/mod.rs:293`, `:315`). `validate` proves its root is A and separately checks Q's security token, but never requires Q to be the admitted process instance. `Snapshot.pid` becomes Q, and `scalar_identity` subsequently verifies Q against that newly adopted Q. All added scalar arguments are nonzero, so the packet reaches `PostMessageW` in Q (`src/input/ffi/native.rs:142`). No identity race is needed. The pre-send sample also reads this recipient's text/pixels (`src/input/ffi/sample.rs:18`, `:86`).

   `TypeText` with a UIA focus handle takes the input branch, bypassing `uia::actions::perform_until` (`src/driver_impl.rs:392`); `input_recipient`, `focus_input` and paste-focus validation likewise omit the new element-owner check (`src/uia/ffi/input.rs:16`, `:44`, `:146`). Thus the semantic-action owner test does not cover these routes.

   Carry the original admitted owner/window binding into recipient resolution and each native job. Verify the child's actual process creation time/owner against that binding outside the pointer gate; do not establish authority from whichever child happens to resolve. Apply the same rule before sampling, SetFocus and paste. Add production-admission tests with a foreign child and assert zero content samples, focus calls and posts. A nonzero-scalar assertion cannot provide this proof.

3. **[P1] Scoped foreground pointer delivery does not check the window actually under the pointer.** Changed purported delivery proof: `gcu-driver-windows/src/input/mod.rs:301`; retained sink: `src/input/ffi/mod.rs:500`, `:519`, `src/input/admission.rs:182`, `:200`; advertised route: `src/driver.rs:211`.

   Schedule: A is the admitted foreground window. An unregistered topmost window B, created with no activation, covers the requested point while A remains foreground. Resolution descends only A's child tree. The final admission verifies A's foreground HWND, stamps, rectangle and DPI, but performs no desktop hit test. The absolute move and button `SendInput` packets therefore reach B. B can already cover the point before the request; this is not merely the final syscall scheduling interval. Every added scalar check succeeds. The same missing receiver check affects intermediate drag points; checking that coordinates fit A's rectangle is insufficient.

   Constrain each scoped pointer packet to the admitted hit target, including capture/drag receiver state, and preserve the existing Stop gate. Disable scoped foreground routes/capabilities where receiver confinement cannot be established. Windows does not inherit ADR 0017's explicitly macOS-only best-effort waiver. Add a nonactivating-overlay case and a drag crossing an unregistered receiver through the native admission seam; assert zero unauthorized down/wheel events. Labeling hit/landing evidence `not_run` in the S9 row does not implement a missing check.

4. **[P1] Queued UIA/capture work drops the admitted incarnation and can read a replacement before the closing refusal.** Changed bracketing: `gcu-driver-windows/src/capture/observe.rs:44`, `:64`, `src/driver_impl.rs:254`; queue payloads/sinks: `src/capture/observe.rs:52`, `src/capture/ffi/mod.rs:87`, `:184`, `src/uia/ffi/mod.rs:138`, `:144`.

   Schedule: the outer observation/capture preflight accepts A at HWND H, incarnation M. Pause before its UIA/capture worker dequeues the job. Destroy A and reuse H for unregistered B with the same rectangle/DPI. The capture job carries only H/frame/scale; native preflight checks liveness, geometry and capture protection, then WGC `CreateForWindow` or `PrintWindow` reads B (`src/capture/ffi/wgc.rs:107`, `src/capture/ffi/print_window.rs:79`). The UIA root job similarly establishes a **new** `WindowIdentity` for B, then builds B's cache; it never receives M to compare against. The later discovery check can discard the result, but the forbidden native content read has already occurred. ADR 0017 §1/§5 requires that read/capture count to remain zero, not just that the final response be empty.

   Pass the immutable admitted process/window/incarnation through both worker requests and verify it on the worker before the first content-producing call. Do not recapture the replacement as the job's authority. Keep the closing checks as well. Capture also queues PNG encoding after its closing check (`src/capture/observe.rs:76`); establish the intended final handoff after that queued work. Test replacement after outer admission but before native dequeue, with spies at the production native source boundary. The current capture test changes creation time before admission and never enters either source (`tests/scope_identity.rs:99`), so it cannot catch this schedule.

5. **[P1] Clipboard payload publication precedes live identity re-verification, including in the parent IPC handler.** Changed check: `gcu-driver-windows/src/input/text.rs:107`; earlier publication: `:77`, `:83`; parent: `src/worker/input.rs:177`, `:198`; actual clipboard sink: `src/input/ffi/clipboard.rs:196`, `:213`, `:225`.

   Schedule: valid A passes the long-text sensitivity/focus checks. Hold clipboard staging before its native job runs, or while its transaction mutex is busy. Destroy A or change its ownership before releasing the hold, without latching Stop. `Paste::run` stages the complete text first. The parent handler checks Stop, approved text and equality of the supplied stamp to the request; it does not query the live owner/incarnation. The clipboard worker receives text/context with no target binding and publishes it. Only afterward do `api.validate`, `before_paste` and the new scalar check reject the lost target. An unregistered clipboard reader can consume the published payload before recovery; restoring the clipboard cannot retract that observation.

   Bind staging to the immutable admitted target and perform live proof at the actual publication boundary after waits, including the parent-owned staging path. Refuse scoped clipboard fallback if that boundary cannot enforce the proof. Keep recovery unconditional. Add an invalidation-before-stage barrier through the real staging/parent handler logic, with a canary and a publication counter; an assertion that Ctrl+V was not sent is insufficient.

6. **[P1] The purported boot identity is a wall-clock estimate, repeating the rejected S2 boot-time fallback class.** `gcu-driver-windows/src/ffi/mod.rs:108`, `:112`, `:123`, `:161`; consumed as evidence by `src/scope_identity.rs:183`.

   Collision schedule: boot B1 with wall-clock origin T yields `floor((now_ms - uptime_ms)/1000) = T`. Boot/reset a second disposable guest at the same clock origin and repeat the PID and process creation FILETIME; B2 yields the same string. The two distinct boots therefore produce equal `ProcessInstance` evidence. No boot-unique OS fact participates, and a nonempty estimate is accepted as proved evidence. Separately, a clock correction or a delay between the uptime and wall-clock reads can make two adapters on the *same* boot disagree; caching fixes only one adapter's subsequent reads.

   Use an independently verifiable OS boot-session discriminator, failing closed when unavailable. Do not promote a quantized timestamp into `BootIdentity`. Add equal-clock/different-boot and same-boot/clock-adjustment source tests. The pure test at `src/scope_identity.rs:350` only supplies different strings to equality; it bypasses `boot_token` and cannot establish that the production source produces different strings. The S9 row's cross-process-consistency `not_run` disclosure does not address the uniqueness defect.

7. **[P2] The new owner policy changes ordinary unscoped UIA behavior.** `gcu-driver-windows/src/uia/actions.rs:64`, `:66`, `:68`; `src/scope_identity.rs:117`.

   Reproduction: use the normal unscoped driver to press a UIA control hosted by Q underneath A/P, with unchanged RuntimeId, properties and ancestry. Previously native `State::validate` accepted that ancestry and dispatched its pattern. The new unconditional `CurrentProcessId` comparison rejects Q against `AppInfo.pid=P` with ScopeDenied, although no fixture scope exists. This is distinct from requiring refusal of the same target in scoped mode. The new successful fake case supplies owner P, and most existing fakes return `None`, which the delivery helper explicitly permits; neither covers the changed real behavior.

   Make scopedness and the admitted binding explicit immutable job inputs, preserve the existing unscoped route, and never interpret missing scoped proof as unscoped permission. If a broader unscoped ownership restriction is intended, give it a separately reviewed compatibility decision and coverage. Add paired scoped/unscoped cases exercising the actual admission path with a reported foreign owner and a missing probe.

Residuals, category (b), and limits:

- **The default isolated parent remains closed, rather than providing a working scoped Windows assembly.** `src/driver.rs:122`, `:369`, `:374` leaves `discovery=None`, so its evidence methods return `None`. The new owner query is before pattern dispatch, not after it, but runs once in a separate job (`src/uia/actions.rs:66`); it is absent from that final guard and from tree/input-focus paths. Do not describe the initial owner test as a per-mutation owner proof. Final same-process check/use remains a platform limit: move E from A to B after the final ancestry check and before Invoke, while A stays alive. No Windows-specific acceptance of that limit is recorded in ADR 0017; evaluate it before enabling native scope, without claiming another preflight makes the OS call atomic.
- **No new Stop/release lock cycle was established.** New enumeration/security work uses the existing native queues/metadata mutex outside the pointer gate and outside the input ledger's send critical section. `release_all_input` still bypasses scope proof (`src/driver_impl.rs:443`); native release bypasses the provider queue and pointer gate (`src/input/ffi/mod.rs:543`). - **No whole-desktop capture fallback was found.** WGC falls back only to window-only PrintWindow (`src/capture/mod.rs:112`), with the original geometry. The blocker is identity loss before that window read, not a newly added monitor capture. The outer scoped wrapper continues filtering discovery and avoids invoking the native restoring `key_window`; direct native geometry/key-window returns have closing checks. Native `key_window` restores before its new closing proof (`src/driver_impl.rs:205`, `:219`), so that check must not be represented as a pre-restore delivery permit.

## 修复记录

1. **Tree/element owner.** `build_scoped_tree` proves each fragment before `properties` and omits a foreign child without reading it. `Walk::prove` calls `admit_delivery_element` and then `admit_fragment` on that production path. `element_binding` requires the source record, calls `admit_delivery_element`, then `prove_element`, and does not inherit the requested window. A handle with no source record is `None`. Semantic `perform_until` and Windows UIA (`open_scoped` / `children_scoped`, before `BuildUpdatedCache`) call the same delivery admission. An unset owner is still refused by `admit_fragment` or `prove_element`. `scoped_snapshot_omits_a_foreign_child_without_reading_it` calls `ScopedDriver::snapshot_tree` and asserts the canary is absent with `content_reads` of that child at 0. `evidence_ignores_path_and_rejects_pid_reuse_hwnd_reuse_and_a_forged_id` expects `element_binding` of a hand-built handle to be `None`.
2. **Foreign input recipient.** `InputBackend::perform_scoped` carries the admitted claim into `resolve_scoped`, then `admit_recipient` compares `recipient_process` with that claim before sample, focus, paste, or send. `RealInput::resolve_scoped` proves a UIA focus fragment before `input_recipient`. `scoped_click_does_not_sample_focus_or_post_a_foreign_child` asserts zero samples, focuses, and posts, then the same click posts when the child owner matches. `unscoped_click_still_posts_a_foreign_child` still posts.
3. **Scoped foreground pointer.** `confine_pointer` checks every scoped foreground pointer packet, including the approach move and drag samples, against `pointer_receiver` (`GetCapture`, then the window under the point, then `GA_ROOT`). Each proved receiver then passes `admit_delivery_element` before send. An unproved or different receiver is `ScopeDenied`. The route stays available when the receiver is the admitted window. `perform_scoped` also calls `admit_delivery_element` on the admitted top-level window before sample, focus, paste, or send. `scoped_foreground_refuses_an_overlay_and_a_drag_that_crosses_another_window` asserts zero button downs for an overlay, a drag that crosses another window, and a captured foreign window, then a down when the receiver is the admitted window.
4. **Queued claim by value.** Snapshot and scoped capture copy the admitted claim, then re-check that same value after the post-admission barrier and before UIA or `take_capture_admitted`. Capture checks it again after PNG encoding and does not return those bytes on failure. The Windows capture worker runs `prove_admitted` before `CreateForWindow` or `PrintWindow`. The UIA worker keeps the `open_root` claim for its children. `replacement_after_admission_does_not_enter_uia_or_capture` replaces the process after admission and asserts zero content reads and zero WGC/PrintWindow attempts.
5. **Clipboard publication.** `Supervisor::start_with_releaser` calls `Recovery::arm_publication`, which calls `set_publish_proof`. On Windows that proof is `prove_parent_publication`: after the clipboard wait and before `EmptyClipboard`, it re-reads the worker generation property, the HWND process, `GetProcessTimes`, and `boot_token(read_boot_session)`. It does not enumerate (`SetPropW` stays on the child). `Recovery::receive` still refuses a scoped `ClipboardStage` before `stage` when the proof is unset. A non-Windows parent cannot make the OS check, so `arm_publication` leaves the proof unset and scoped clipboard stays closed. An HWND whose process is not the admitted owner, including ApplicationFrameHost that the parent cannot unwrap, is refused and not published. Restore still runs. `scoped_clipboard_stage_refuses_before_publish_when_the_parent_has_no_proof`, `scoped_clipboard_invalidated_during_the_wait_does_not_publish`, and `scoped_parent_publication_is_armed_and_refuses_an_unproved_window` assert zero publications and that the canary is absent.
6. **Boot identity.** `boot_token` ignores the wall-clock argument and rejects an empty, oversized, or all-digit session. `RealWinApi::new` passes `read_boot_session` (`NtQuerySystemInformation` class 90) and stores an empty string when that query fails. The same function is the portable proof: `live_process`, `live_window`, `scope_close`, `carried_claim`, and `prove_carried` all pass the session through `boot_token`, so a numeric session is not evidence on non-Windows builds either. `boot_token_uses_the_session_and_ignores_the_wall_clock` covers equal clocks on different sessions, one session across a clock change, and numeric rejection. `portable_live_process_rejects_a_numeric_boot_and_accepts_a_session` covers the live proof.
7. **Unscoped UIA.** `actions::perform` passes `JobScope::Unscoped` and does not consult the owner probe. `JobScope::Missing` is a refusal. `unscoped_uia_pattern_dispatch_is_unchanged` and `unscoped_uia_invoke_allows_a_foreign_owner_and_a_missing_probe` dispatch a foreign owner and a missing probe. `scoped_uia_pattern_dispatch_requires_the_element_owner` refuses those cases, a crossed hwnd, and `JobScope::Missing`, and dispatches a matching owner.

ADR 0013 constants, the pointer gate, settle, fail-closed, and the one bounded retry are unchanged. Scoped foreground is not globally disabled. InProcess was not enabled.

Production-path check of round-1 items 1, 3, and 5: item 1 is enforced by `admit_delivery_element` plus `admit_fragment` / `prove_element` on the tree, evidence, semantic, and Windows UIA paths before content or cache. Item 3 is enforced by `confine_pointer` calling `admit_delivery_element` for every scoped foreground receiver before send; the route stays open when that receiver is the admitted window. Item 5 is enforced by `arm_publication` → `set_publish_proof` on the parent supervisor. The Windows proof runs inside `stage_proved` after the wait. Where the parent cannot prove the target, scoped clipboard is closed and nothing is published.
