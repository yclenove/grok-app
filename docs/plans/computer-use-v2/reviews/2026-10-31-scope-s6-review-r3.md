Must-fix, category (a), before merge:

1. **[P1; SAME CLASS as round-1 A1 and round-2 finding 1] The public fake-client slot still lets a relocated caller authorize an arbitrary sibling executable.** `gcu-eval/src/runner.rs:253`, `:258`; `src/boundary.rs:47`, `:60`, `:88`, `:99`, `:108`, `:112`; `src/disposable.rs:582`, `:585`; `src/launch.rs:72`, `:74`, `:94`.

   Schedule using an existing genuine executable, without changing its code: copy the Cargo-built `gcu-eval` integration-test executable for `tests/runner.rs` into a fresh directory D (directly in D, not a `deps` subdirectory), and place a regular executable shell wrapper at `D/eval-fake-agent`. Have the wrapper write an absolute start-sentinel path using shell `printf`/redirection and exit 0; no PATH lookup is needed. Run the relocated executable with `--exact run_success_records_calls_and_destroys_env`, with the bundled source fixtures still present. `tests/runner.rs:30`, `:43`, `:55`, `:217` derives that sibling path, selects `builtin_fake=true`, leaves `gcu_bin=None`, and invokes the production `run_tasks` path. Equivalently, a library caller supplies that public configuration to `run_tasks` with a valid task.

   The wrapper passes the regular-file/name/directory checks; `artifact_dir()` treats D as the build directory solely because the caller is there. `launches_real_client` returns false. The shared **backend** check accepts the absent backend, so `refuse_unsupported_launch` returns None and no provider report is created. `resolve_client` returns `ClientProgram::Path(wrapper)`; `execute_ready` skips real-client preflight (`src/exec.rs:64`) and starts the wrapper (`:77`, `:88`). The test's subsequent Pass assertion will fail, but the start sentinel has already been written. A wrapper can instead set `GROK_HOME` to a prearranged credential directory and exec an absolute client binary, including its tool-preflight invocation. Clearing the inherited environment does not prevent that execution or filesystem access. No provider evidence, attestation flag, race, hard link, replacement of an original artifact, or modification of the genuine caller is required. The Windows name/directory classification has the same gap with an executable sentinel named `eval-fake-agent.exe`.

   After an ordinary wrapper exit and successful directory cleanup, the outcome has no environment refusal or cleanup failure. `InheritedStop::from_outcome` (`src/runner/provider.rs:116`) therefore does not halt a multi-task/library A/B run; this boundary failure is treated as an ordinary scored client result. This is a retained public-library launch bypass, not a remaining disagreement between two genuine fake-agent backend decisions. The CLI does not expose `builtin_fake_bin`, which limits ordinary CLI exposure but does not close the public API. The heuristic predates this branch; S6's new gate still relies on it. It also matches PR #162's historical public-test-slot finding N1.

   Fix direction: remove placement-based fake-client authority from the production API as well as the backend API. Make runnable fake-client selection resolve to the implementation/self-entry owned by the caller, or establish executable identity independently of caller-controlled placement and keep it bound through spawn. Any arbitrary path must be classified external and receive `provider_unavailable` / `not_run` plus run halt before allocation or dispatch. A renamed boolean or adjacent-file check is insufficient. Add a bounded relocation/start-sentinel regression through actual `run_tasks` and `run_ab`, covering later-task/arm/repeat suppression and report provenance, with a genuine fake-client positive control. `tests/lockdown_r4.rs:118` only puts the wrapper outside the original artifact directory; the new relocation tests relocate the fake-agent caller and forge its **backend**, not the runner's **client**. Neither catches this schedule.
