1. **must-fix / P1 — Malformed observations can be retried away and followed by measured success.** `src/run.rs:505`, `src/run.rs:515`, `src/run.rs:486`.

   **Failure scenario:** virtiofs exposes a stable short ping, such as 4095 bytes, for one poll, then exposes the complete 4096-byte ping on the next poll. The same-FD checks can legitimately return the first short snapshot: it is an ordinary, single-link, capped file whose metadata remains stable during that read. `accept_ping` returns `Ok(false)` for every non-4096 length. `wait_bytes` forgets those observed bytes and retries; the later valid ping is acknowledged. Similarly, a short pong with a damaged version/prefix, invalid UTF-8, or an incomplete record generally returns `Ok(false)` from `accept_pong`. A subsequent valid pong completes the round. All rounds can then produce `verdict=ok latency=measured torn=0`, despite an observed incomplete/torn publication. The pong path also skips every valid 4096-byte frame, irrespective of its tag/direction/sequence, rather than checking the exact permitted leftover.

   This regresses the previous reader's immediate rejection of malformed frame bytes. A missing name is retryable; an observed invalid object must not become equivalent to absence.

   **Minimal fix:** make the classifiers distinguish only absence and an exact, permitted old-phase object from invalid evidence. Reject all other observed bytes as sticky `Torn`/`BadPong`/`Bad`, including short pings and malformed pong framing. Using separate names for the two phases, as in finding 3, removes the need for most old-object exceptions. Preserve the existing refusal to retry `RdErr::Replaced`. Add controlled malformed-ping-then-valid and malformed-pong-then-valid cases; neither may recover to measured success.

2. **should-fix / P2 — Guest-summary collection loses integrity errors and introduces a fresh deadline.** `src/run.rs:787`, `src/run.rs:740`.

   **Failure scenario:** all reverse pings are answered, but `summary-guest` is replaced during its verified read. `load_summary` returns `Stop::Replaced`; the catch-all at line 789 reports `unknown/no-peer-summary` with `integrity=ok`, losing the observed integrity violation. In the earlier-error path, `guest_gh` discards every collection error with `.ok()` and may reread after that violation. It also creates `now + 250ms` even when the original command end has expired. These paths remain non-successful, so they do not create a completed C1 pass, but they weaken the promised sticky classification and absolute-end discipline.

   **Minimal fix:** carry the typed summary-read error through the existing `stop_view` mapping while retaining the accumulated host and available guest samples. Preserve `failed/replaced` and `failed/nofollow`; reserve missing-summary/unknown for genuinely unavailable evidence. Remove the post-end grace read, or clamp any remaining diagnostic read to the original end. Unavailable guest samples may remain unavailable; do not recover them by retrying an observed integrity error.

3. **should-fix / P2 — Reusing the first phase's files creates a healthy-exchange race; the success test also assumes fast scheduling.** `src/run.rs:560`, `src/run.rs:577`, `src/run.rs:1293`, `src/run.rs:1306`, `src/run.rs:1340`; supporting checks at `src/io.rs:351` and `src/io.rs:356`.

   **Failure scenario:** after host→guest completes, `guest-write/f-1` still contains its pong. The host's reverse-phase responder opens that old pong. Before the final same-FD/name checks, the guest atomically replaces it with the valid reverse ping. The read correctly returns `Replaced`, and the protocol reports a torn/replaced failure for an otherwise healthy exchange. The equivalent window exists when the guest opens the original host ping while waiting for its reverse pong. This is a concrete scheduling race in `ping_pong_both_directions_measure_rtt_on_one_clock`, and could explain an intermittent failure; a failure transcript is needed to identify the reported occurrence. It fails closed and therefore is not a safety blocker under this review's severity bar.

   **Minimal protocol fix:** use distinct fixed names for each direction's ping/reply pair, with matching bounded whitelist updates, or establish an explicit transition that avoids reading the old object while its successor is published. Keep all same-FD/name checks. Do not fix the flake by broadly ignoring replacement errors. Make the race deterministic with a named read hook and channel/barrier: pause after reading the old inode, publish the successor, then resume verification. Test the chosen protocol behavior at that exact boundary.

   **Deterministic timing assertions:** line 1306 requires `gate=-` even though a correctly measured round can take 2–3 seconds under load and legitimately report `exceeds-2s`. Check that the emitted gate agrees with the observed maxima; the pure threshold test at line 1443 already supplies deterministic fast/slow boundary cases. `missing_pong_times_out_and_keeps_the_sample` is independently wall-clock sensitive: its helper must deliver pong 1 within three seconds, and line 1340 assumes the entire call takes less than seven seconds. Synchronize helper readiness and test round expiration with a small injected clock/wait seam. Assert preserved samples and timeout classification from controlled events, retaining a separate generous external hang watchdog. More repetitions or longer sleeps do not establish either property.

4. **should-fix / P2 — Phase-summary validation no longer checks the digest binding and only checks the shape of RTT statistics.** `src/run.rs:363`, `src/run.rs:646`, `src/run.rs:732`, `src/run.rs:799`.

   **Failure scenario:** a malformed summary can carry the expected role/count and `torn=0`, but an unrelated digest; `phase_ok` never examines `digest`. The former `judge_summary` compared it with the observed frames. RTT parsing accepts contradictory `min/p50/max` values and uses the first matching direction tag, so duplicated direction sections or `min=2500000,p50=2500000,max=1` are accepted. The latter reports a clear sub-two-second gate from `max=1` despite its contradictory statistics. The normal formatter emits consistent records; this finding concerns validation of malformed mailbox evidence, not authentication of a hostile guest's claimed timings.

   **Minimal fix:** decode each phase summary once into its closed expected fields: exactly one `hg` and one `gh`, the expected active and empty sides, exact counts, ordered `min <= p50 <= max`, the applicable percentile rule, and the expected direction/count frame digest. Keep explicit partial/error records valid without treating them as complete phases. Derive the gate from the validated maxima. The bash layer can continue passing through the resulting record without duplicating Rust's statistics evaluator.

5. **should-fix / P2 — Delete repeated result assembly and parsing rather than adding more error arms.** `src/run.rs:414`, `src/run.rs:437`, `src/run.rs:616`, `src/run.rs:704`, `src/run.rs:759`, `src/run.rs:793`.

   **Failure scenario:** the many long `emit(...)` calls repeat the same counts, clocks, digest, RTT prefix, visibility marker, and summary flag. They already differ in error classification as described in finding 2. Each added failure case must reconstruct this state correctly. Total file growth is 511 lines (1115→1626); lines before the test module grew by 384 (839→1223), so the growth is not solely tests.

   **Minimal deletion targets:**

   - Collapse the three repeated `rec_text` + `decode(C1_KEYS)` pairs and their identical bad-record exits at lines 704/707, 759/762, and 793/796 into one C1-specific decoder returning a typed error.
   - Keep one small C1 result context containing accumulated clocks, counts/digest, and direction statistics; let its failure/finish methods supply the repeated arguments. This can replace the long repeated return arms in `c1_host_reader` and the 15-argument `emit` interface while preserving partial samples.
   - Replace the seven repeated optional-clock updates in both `merge_clock` and `absorb_nums` with short fixed-field iteration; retain maxima and the current unknown-value checks.
   - Share the publish-result/error-to-`Stop` handling duplicated in `drive` and `respond` at lines 548 and 585, while keeping the initiator timestamp and responder frame accounting explicit. Return borrowed slices from `side_of` instead of cloning samples solely to format them.

   Preserve typed integrity failures, original ends, actual IO timers, and partial statistics during these deletions. No general record framework or new orchestration layer is needed.
