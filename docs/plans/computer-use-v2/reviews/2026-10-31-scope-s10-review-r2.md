## 修复记录

Round-2 must-fix items, addressed on this branch. Stop constants are unchanged (100 ms latch, 500 ms release, 5 s native, 4750 ms driver). No `Cargo.toml` or lockfile change. These regressions were not executed here; this workspace has no compiler.

1. **A1 scoped doctor leaves the runtime.** When a scoped driver has an X server and the portal early return does not apply, Composite and XTest are probed only inside `off_runtime` under the existing `NATIVE_TIMEOUT`. The probe does not call `begin_evidence_action`, and the worker does not own input release. A timeout, a latched driver Stop, or a thread-start failure returns a closed report (`ready` false, empty issues). Unscoped doctor still probes on the caller thread. The portal path still uses the captured `PortalInfo` and does not touch X. `stalled_scoped_doctor_releases_stop_while_the_extension_probe_is_blocked` arms the FakeX extension stall after assembly, calls `ScopedDriver::doctor` on a current-thread runtime, latches Host Stop from another thread, and runs `Session::handle_stop`. It records the key-up and an empty ledger while the probe is still blocked, and checks the 100 ms latch and 500 ms release budgets with an external wall clock. FakeX release reads the XTest flag and does not enter that stall. RealX `cookie.reply` can still hold that X connection on the evidence thread, the same residual already accepted for evidence capture; the runtime does not wait on the reply.
2. **A2 scoped discovery binds the unique owner before the name.** `GetNameOwner` runs before any name or content query. Only a peer unique name (leading `:`, containing `.`) is accepted; `org.freedesktop.DBus` and unresolved references are skipped. `GetConnectionUnixProcessID` is called on that unique name, not on the well-known name. The accessible name is read from that same connection only after pid, start time, and boot id match every registered window of the original bus name. The published id is the original bus name; the name and pid come from the verified unique connection. A failed identity check publishes nothing. Unscoped `list_atspi_apps` is still name-then-pid. `handed_off_bus_name_does_not_publish_the_previous_owners_name` stalls the in-process bus on the pid method, hands the well-known name from C to P while P stays alive, and asserts the pid query was C's unique name, no name was read, and neither list nor resolve publishes C's canary. `verified_unique_owner_publishes_its_own_name` is the matching-owner control. `bus_name_held_by_another_pid_publishes_nothing` is the P-to-C mismatch through the same bus.
