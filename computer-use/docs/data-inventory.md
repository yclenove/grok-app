# P9-04 数据持有、权限与清理清单

基线与审阅范围同 [security.md](security.md)。这是一份源码清单，不是运行通过证明。引用均从仓库根解析，`文件.rs#测试名` 表示现存自动化用例；本次运行结果均 not_run。Unix 模式和 Windows DACL 分开记录，未实现/未确认的权限不以“私有目录”替代。删除表示逻辑撤权或 unlink，不保证内存清零、磁盘安全擦除、备份/OS 剪贴板历史或外部 MCP 客户端副本被删除。

“置 1 时日志脱敏”列仅讨论日志入口，不表示 at-rest 内容也被替换：token 必须在可信内存/FD 内保持原值。`GCU_LOG_PAYLOADS` 只在 `computer-use/crates/gcu-host-protocol/src/log_policy.rs` 读取：非精确 `1` 为 metadata-only；精确 `1` 才允许文本载荷，且必须先经字段与已登记 bearer 脱敏，不能用该开关取消脱敏。无字段名的自由文本密码不在清洗范围内。`yes` 表示对应受限类型的静态防线，`metadata-only` 表示记录内容只含所列元数据，`not_run` 表示全链脱敏未证明，`not_implemented` 表示尚无该存储实现。

会话结束、撤销和删除是不同边界：turnEnded 清本轮授权/输入并保留会话图片；session.close/删除聊天/fork/切模型由 Lifecycle 先使凭据/图片索引失效再清文件；policy.changed 更新授权并取消不合格动作，不等于已交付图片或聊天历史被立即物理擦除。Always policy 和用户 Stop 按产品要求跨会话保留，不能为了清理数据绕过可信恢复。

当前 `journal` 指实际 App 聊天持久化，不存在额外 CU 专用 journal 文件。D11 是获批设计但尚无落盘实现；不要将其伪写成已具备 0700/0600/DACL 的数据。L1 隔离浏览窗 profile、DOM 生产通道未交付，不声称存在已验收的数据清除路径；启用前按 ADR 0010/0012 补 cookies/cache/service worker、DOM/pending 与所有图片衍生物清单，不能读取真实浏览器或账号。
