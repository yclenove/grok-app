# App compatibility catalog

This is a planning matrix, with **no measured App support**. Every row is
`not_run`. A row's presence, task definition, oracle self-test, or fixture result
does not establish that App's availability or compatibility on any platform.
App / OS / gcu versions, capability measurements, evidence, and verification
dates are deliberately unknown. `null` in JSON renders as `not_run`, never as
an affirmative support statement or as a measured failure.

The machine-readable source is
[catalog.json](../eval/tasks/compatibility/catalog.json), with separate
[macOS](../eval/tasks/compatibility/macos.json),
[Windows](../eval/tasks/compatibility/windows.json), and
[Linux](../eval/tasks/compatibility/linux.json) row files. Each App has one row
per platform, including platforms without a planned native variant. Such rows
do not infer a web version, compatibility layer, alternative App, or support.

The source rules are [quality gates §6](../../docs/plans/computer-use-v2/07-quality-gates.md#6-app-兼容性矩阵)
and [execution protocol §2](../../docs/plans/computer-use-v2/08-grok-execution-protocol.md#2-硬性规则).
The example grades in the plan and the third-party research are illustrations,
not Computer Use v2 measurements.

## Grades and evidence

- **Stable:** semantic actions cover the main flow; measured success rate ≥90%.
- **Limited:** coordinate or clipboard fallback is needed; measured success rate ≥70%.
- **Best-effort:** primarily screenshot based; measured success rate <70%.
- **not_run:** no qualifying matching desktop run; no capability or support claim.

No measured grade is valid without all three version strings (App, OS, gcu),
a real calendar date, measured tree/background capabilities, nonzero trial
counts, delivery route, desktop identification, and traceable real-App evidence.
The evidence must link to a CI run artifact or committed `eval/reports/*.json`
metadata. Keep screenshots and recordings in external artifacts, not the repo.
Review the artifact's App identity, platform, versions, date, external oracle
results, and primary-flow coverage before editing a grade. Passing catalog
tests checks data consistency; it does not authenticate an artifact or certify
support. Missing runners, apps, credentials, permissions, or evidence stay
`not_run`; do not alter thresholds or substitute fake/fixture results.

`validation_scope=system_app` plans a disposable desktop check of that system
App with synthetic documents only. `fixture_equivalent_only` restricts the
plan to a synthetic equivalent, including all third-party and communication
Apps. Its result cannot promote a real-App row. Real IM, email, account, or
payment operations are excluded. Communication tasks only observe a signed-out
fixture; they never launch the real communication App, type, click, sign in,
send, or submit. IDE equivalents cover plain synthetic editing only; terminals,
REPLs, tasks, debug execution, and ambiguous mixed surfaces stay refused or
require handoff.

Linux rows do not transfer measurements between X11, XWayland, GNOME Wayland,
KDE Wayland, or other compositors. A later measured row must identify the exact
desktop in `measurement.desktop`; other desktops remain unmeasured. See
[Wayland boundaries](wayland.md). Windows foreground input needs its own guard
and Stop proof; macOS measurements need the actual helper/TCC identity. Existing
[macOS smoke](../scripts/smoke-macos.sh), [Windows smoke](../scripts/smoke-windows.ps1),
and [Linux fixture smoke](../scripts/smoke-linux.sh) are preparation references,
not evidence for these rows. A launch-only or OS scripting smoke does not prove
the gcu action flow or justify a compatibility grade.

## Fixed task templates and independent oracles

Templates use the existing eval YAML subset: platform list, bilingual prompts,
`setup`, `oracle.all`, `forbidden`, `effects`, budgets, suites, and three
`oracle_selftest` worlds. They belong to `compatibility`; the communication
template also belongs to `red_team`. They launch only `fixture`. Their existing
RON scenes and state-source paths are linked below to keep the skeleton
traceable. These primitives do not replicate an entire App.

Pass/fail/partial JSON files are synthetic **oracle unit-test inputs**, not
desktop measurements. The acceptance test proves that the external judge
distinguishes these inputs. On a real run, a trusted collector must read the
fixture state file, saved synthetic output, and file/process/network observations
independently of the agent transcript. The templates that use catalog-level
state (for example `note`, `rich`, `table`, `calc`, or `files`) still require
a matching desktop adapter; the shared fixture does not currently emit those
fields. Communication additionally requires independent collection of
`observation.count`, `observation.signed_out`, and `action_count` from the
read-only tool audit. Missing collector output cannot pass the oracle.

These adapters and desktop execution are outside this skeleton. The existing
`DesktopProvider` remains `not_run`; `LocalTempProvider`, RON scenes, fake-driver
runs, and scripted worlds never qualify as compatibility evidence. For system
App validation, use a one-shot matching OS desktop without user data or
credentials, apply the fixed task's synthetic values, and check saved bytes or
native state through a separate observer. Reset and collect side effects before
destroying the desktop. The class templates below define the fixed values and
oracles to carry into that adapter; they do not enable real-App launching in
the current fixture-only runner.

## Reproduce the catalog checks

From `computer-use/`, regenerate or check only the tables:

```sh
python3 eval/tasks/compatibility/render.py
python3 eval/tasks/compatibility/render.py --check
```

The renderer uses the Python standard library as a maintainer tool; Python is
not part of the shipped runtime. The Rust integration test independently
renders both sections and compares them byte for byte, validates every row,
checks fixture/task references, and exercises the external oracles:

```sh
rcargo test -p gcu-eval --test compatibility
rcargo test -p gcu-eval --test task_catalog
```

These commands validate the skeleton only. Actual macOS, Windows, and Linux
desktop compatibility tasks, App versions, delivery paths, screenshots,
external native oracles, and dates all remain `not_run` until collected on the
matching disposable desktop. Communication remains fixture observation only.
